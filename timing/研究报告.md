# USB HID 硬件输入注入检测 — 研究进度报告

## 1. 研究定位

从**系统层面**识别"伪装成键盘的 USB HID 注入设备"，建立从设备描述符到输入行为的
多层检测方法学。研究构建**未伪造的**注入样本作为基准，用以标定检测规则的有效性。

- 攻击样本（基准）：Pro Micro (ATmega32U4) 原样构建的 USB HID 键盘注入器
- 检测环境：Windows 11 主机
- 采集工具：PowerShell PnP 查询、hidapitester、pynput

---

## 2. 三层检测成果

### 2.1 设备描述符层

**方法**：枚举系统 HID/键盘设备，提取 VID/PID、厂商/产品字符串、接口所属设备类。

**基准样本（Pro Micro）暴露的指纹**：

| 维度 | 基准样本 | 真实键盘（对照） |
|------|---------|-----------------|
| VID:PID | `2341:8036`（Arduino LLC，公开分配） | `1CA6:0103`（厂商私有） |
| 产品字符串 | `Arduino Leonardo` | `VGN Flash Keyboard` |
| 厂商字符串 | `Arduino LLC (www.arduino.cc)` | `VGN Flash Keyboard` |
| CDC 串口接口 | **有**（出现在 `Ports` 类） | 无 |

**检测规则（任一命中即告警，串口最硬）**：
1. 设备是否在 `Ports` 类出现 CDC 串口接口（真实键盘无）
2. VID/PID 是否命中已知开发板池（`2341`/`1B4F`/`16C0` 等）
3. 字符串是否含 "Arduino"/"Pro Micro" 等关键词
4. InstanceId 前缀是 `ROOT\`/驱动前缀（软件注入）还是 `USB\`（硬件）

**采样证据**：系统内 `USB\VID_2341&PID_8036` 出现 4 条（父设备 + MI_00 串口 + MI_02 键盘 ×2），
构成典型的 CDC+HID 复合设备，与真实键盘的纯 HID 结构形成对照。

### 2.2 报告描述符层

**方法**：用 hidapitester 抓取设备原始报告描述符（report descriptor），与真实键盘逐字节对比。

**基准样本报告结构**：
```
05 01 09 06 A1 01 85 02 ... 75 08 95 06 81 00 C0
→ Generic Desktop/Keyboard；Report ID=2；1字节修饰位 + 1字节保留 + 6字节按键数组（6KRO）
```

**对照键盘（VGN 主键盘）报告结构**：
```
05 01 09 06 A1 01 85 01 ... 75 01 95 78 81 02 C0
→ Report ID=1；120 个 1-bit 字段（NKRO bitmap，每键 1 bit）
```

| 维度 | 基准样本 | 真实键盘 |
|------|---------|---------|
| Report ID | 2 | 1 |
| 按键编码 | 6 字节数组（6KRO） | 1bit/键 bitmap（NKRO，120 键位） |
| Consumer Page (0x0C) | 无 | 有（多媒体键接口） |
| Output/LED 报告 | 无 | 有 |
| HID collection 数 | 1（仅键盘） | 多个（键盘+多媒体+系统控制） |

**检测规则**：读取报告描述符，判断按键编码方式（bitmap vs 数组）、Report ID、是否含
Consumer Page、是否存在 Output 报告、collection 数量，与真实键盘基线比对。

### 2.3 行为时序层

**方法**：pynput 系统级采集按键 down 事件时间戳，计算相邻间隔，做统计分布分析。
实验采集三类样本各一组（同一目标键连击，场景对齐）。

**实测数据**：

| 样本 | n | mean (ms) | std (ms) | cv | min | max |
|------|---|-----------|----------|-----|-----|-----|
| 真人连击 | 131 | 150.40 | 21.43 | **0.143** | 104.99 | 277.47 |
| 固定间隔注入 | 99 | 105.09 | 1.56 | **0.015** | 98.51 | 111.49 |
| 均匀随机注入 | 99 | 107.39 | 23.11 | **0.215** | 66.94 | 145.13 |

**分布对比（KS 检验）**：

| 对比 | D | p |
|------|---|---|
| 真人 vs 固定注入 | 0.977 | 3.9e-62 |
| 真人 vs 随机注入 | 0.759 | 1.5e-32 |
| 固定 vs 随机注入 | 0.475 | 1.8e-10 |

**关键发现**：
1. **固定间隔**：`cv≈0.015`，与真人差一个数量级，秒杀级信号（R1）。
2. **均匀随机**：`cv=0.215` **反而比真人高**——"加随机"并未提升隐蔽性；其**矩形分布**与
   真人的**偏态分布**在 KS 检验下显著不同（D=0.759）。说明随机化只是把"cv 秒杀"
   变成了"分布形状秒杀"。
3. **边界特征**：均匀随机样本 `min/max` 存在清晰硬边界（60/140 截断），真人分布无硬边界、有长尾。
4. **数据自洽**：固定样本 mean 精确等于 `100ms + 5ms` 按键时长；随机样本 std 精确等于
   `U(60,140)` 理论值 `80/√12 = 23.09ms`，验证采集链路无误。

**检测规则（阶段 3）**：

| 规则 | 判定 | 针对 |
|------|------|------|
| R1 | `cv < 0.05` → 固定间隔注入 | 常量间隔 |
| R2 | KS 检验 vs 真人基线 `D > 0.4` → 分布异常 | 均匀/其他非真人分布 |
| R3 | 分布拟合优度：真人≈对数正态/伽马，注入≈均匀 | R2 的加强版 |
| R4 | 间隔存在清晰 min/max 硬边界 | 均匀分布辅助信号 |

**场景限定（重要）**：真人"连击"（肌肉记忆）cv≈0.14；真人"打字"（含认知停顿）cv 可达 0.98。
检测必须**场景对齐**，否则误伤真人。

## 3. 检测规则总表

| 层级 | 检测对象 | 核心规则 |
|------|---------|---------|
| L1 设备描述符 | 设备身份 | CDC 串口 + 开发板 VID/PID + 字符串关键词 |
| L2 报告描述符 | 报告结构 | 按键编码方式 / Report ID / Consumer Page / Output 报告 / collection 数 |
| L3 行为时序 | 输入节奏 | cv 阈值 + KS 分布检验 + 边界检测 |

三层相互独立、可叠加，形成纵深检测。

## 4. 代码产出（`timing/`）

| 文件 | 作用 |
|------|------|
| `key_capture.py` | 系统级按键事件采集器（纳秒时间戳，支持 `--key` 过滤） |

| `remote_agent.py` | 测试机端：串口 + TCP 转发 |
| `remote_send.py` | 控制端：远程发送注入指令 |

---

## 5. 结论

1. 硬件 HID 注入设备在**三个层面**均留下可检测特征：设备身份、报告结构、行为时序。
2. 检测难度递增：L1 最廉价但可被伪造规避；L3 最难规避（需拟合真人分布统计特征）。
3. 简单"随机化"不能提升注入隐蔽性——只从"cv 秒杀"变成"分布形状秒杀"，验证了
   分布级检测的必要性。
4. 检测规则库 + `detector.py` 可支撑一个实时的注入检测原型。

## 6. 后续（均为检测侧）

- **实时化**：将 `detector.py` 从离线分类升级为持续监控输入流的实时报警器。
- **红队验证**：用基准样本原样注入，测检测器漏报率/误报率，量化三层规则的检出效果。
- **对抗演进研究**（threat model，仅分析不实现）：注入方未来可能的对抗手段（伪造 VID/PID、
  伪装 NKRO、拟合分布）及检测方对应的识别思路。

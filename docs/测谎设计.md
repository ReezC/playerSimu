# 测谎（自动鼠标跟踪）设计

**这份文档只写「契约」**：问题本质、算法路线、每个里程碑的判据、和别的模块怎么划界。

`gui/live_thread.py`（接线）、`decision/input.py`（鼠标，已有 ✓）。

## 1. 目标（用户原话口径）

测谎弹窗出现后，**自动移动鼠标保持在那个"旋转 + 随机位移"的图形内部**，直到成功弹窗
出现按 Enter 回战斗。图形行为：

- 弹窗一开始展示**白色实体**的目标图形（形状多模态完全随机、大小在一定范围内），
  倒计时结束后图形开始**随机运动**，白色逐渐消失变**透明**（轮廓保持），持续旋转；
- 背景中还有**其他相同形状的透明图形**（干扰项），它们的运动轨迹基本相同且基本
  **相对背景静止**（背景相对弹窗视口是运动的）；
- 一段时间后弹成功弹窗，按 Enter 回战斗。

## 2. 素材盘点与结论（2026-09-29）

`datasets/liedetectorphotos`：70 个 cycle（`cycle_00211`~`00281`），每个约 12 秒
（完整小游戏时长）、~6 fps、文件名带帧内时间戳；帧是 **750×500 的弹窗视口裁剪**
（录制时已裁好，不是全屏 ✓）。另：`datasets/train` 有用户引入的 YOLO 模型
（自动标注用，M2b 消化）。

**看过开局 / 中段 / 末段帧后的问题本质结论**（算法路线的依据）：

1. **开局白色实体阶段是唯一的"认识你"机会**：0.3s 帧里目标是清晰白色块 + 倒计时数字；
   5s 之后目标完全透明融入花纹背景，**单帧不可辨认** ⇒ 追踪必须
   **"白色阶段初始化 + 帧间运动连续性"**，纯外观检测（YOLO/模板）在后期救不了 ✗；
2. **目标 = 唯一"运动方式与背景不同"的东西**：干扰项与背景一起滚动 ⇒
   估计帧间全局运动（背景运动场），**残余运动**就是目标 —— 对透明免疫（用时序差分，
   不用外观）；
3. 6 fps 素材下目标帧间位移可观 ⇒ 相邻帧差分/相位相关的搜索窗口要留够
   （回放器跑一遍就知道实际位移分布 ✓ 不拍脑袋）。

## 4. 关键技术前提（已核实 2026-09-29）

- **鼠标通道全通**：`decision/input.py::mouse_move(dx,dy)` 相对移动 → TLS/串口 →
  Pro Micro 固件 HID（±127 分块 ✓）。press/release/click/drag/scroll 全有 ✓。
- ⚠ **只有相对移动，没有绝对定位** ⇒ 闭环靠**光标在流画面里可见**（素材里可见 ✓）：
  需要**增益标定**（发 `MOVE 100 0`，量流画面里光标实际位移 ⇒ 得到比例系数；
  Windows 指针加速可能非线性 ⇒ 标定要在游戏窗口聚焦状态下做）。
- **接管期间禁战斗键**：lie_game 状态已在 takeover 名单 ✓（M1 做了）；
  追踪节拍挂在同一处。

## 5. 排期（里程碑与判据）

### M2a 离线回放器 + 追踪器原型（不碰实机，先在素材上过）

- **`perception/lie_tracker.py`**：输入弹窗视口帧流，输出每帧目标质心（或"丢失"）。
  路线：① 白色实体阶段初始化（高亮块 + 面积/形状过滤）；② 帧间全局运动估计
  （相位相关）⇒ 补偿背景滚动；③ 差分残差里找连通域 ⇒ 与上一帧目标位置做
  **运动连续性关联**（预测 + 匈牙利/最近邻）；④ 丢失 N 帧 → 报丢失（**不猜**）。
- **`tools/lie_replay.py`**：读 cycle 目录按时间戳逐帧喂 tracker，输出每帧
  "假设鼠标在上一帧输出位置，是否在目标内"的曲线 + 每 cycle 汇总
  （命中率 / 首次丢失时刻 / 丢失总帧数）。
- **判据**：70 个 cycle 全部跑通；**先跑通再调优**——第一版只要求
  "白色阶段 100% 初始化成功、透明阶段平均命中 ≥ 50%"，之后按报告迭代
  （目标 ≥ 80% 后才进 M2c）。⚠ 命中率用**合成鼠标轨迹**近似（鼠标 = tracker 输出
  滞后一拍），不是真鼠标 ✓ 离线阶段够用。

### M2b 形状检测器训练（辅助通道，可与 M2a 并行）

- 用 `datasets/train` 的 YOLO 标注模型预标注 27k 帧 → 人工抽检 10% → 训练二代检测器。
- **定位**：只做 M2a 追踪器的**校验/复活通道**（追踪丢失时用检测器重找候选），
  不做主追踪（透明+旋转外观检测不可靠，见 §2）。

### M2c 鼠标闭环（半实机：真鼠标 + 录制回放画面）

- **增益标定工具**：`tools/mouse_gain_calib.py`（发 MOVE → 流画面量光标位移 → 存
  `config/mouse_gain.json`）；指针加速开着也能用（闭环自校正，但标定要同状态做）。
- **控制律**：`perception/lie_controller.py` —— P 控制（质心−光标 × 增益）+ 目标速度
  前馈（**限幅** 300px/s，防跳变把指令甩飞 ✗）+ 死区 3px + 单步限幅 + **丢失保护**
  （丢 N 帧 ⇒ 光标**原地停住** ✓，持续丢失 ⇒ `lost_event` + 等成功/失败弹窗兜底 ✓）。
- **判据**：对 70 个 cycle 的回放画面接真鼠标跑，命中率与离线一致（±10%）。
  ⚠⚠ **判据的口径（2026-09-30 实测踩过 ✓）**：两条口径必须在**同一时刻**取样 ——
  离线 = 该帧**上一拍输出**；闭环 = 该帧**已知的光标位置**（= 上一拍指令落地后 ✓）。
  拿"上一拍光标"比"上一拍输出"会**白送闭环多一拍滞后** ⇒ 判据恒差 ~0.13 ✗
  （测量口径错会让人去改本来没毛病的控制律 ✗）。
- **离线预演**：`tools/lie_closed_loop.py`（目标流 = 追踪输出 ✓ 感知两端不变 ⇒ 差异
  只来自控制律；`--gain-true` 测标定错的鲁棒性、`--no-feedback` 反向验证）+
  `tools/selftest_lie_controller.py`（收敛/死区/限幅/丢失保护/增益错自校正 ✓）。

### M3 实机接线 + 灰度

- live_thread 检测节拍接 tracker（lie_game 状态每拍跑）；弹窗视口矩形从
  lie_game 模板命中位置推（⚠ 窗口模式要多尺度——顺带把 M1 遗留的多尺度做了）。
- 成功弹窗 Enter（走既有 takeover 流 ✓）；**失败弹窗**要加检测（首次实测没见过
  失败帧 ⇒ captures 自愈闭环攒）。
- 打点：`perf` 加 `lie_track`（cycle 开始/结束/命中率）、`behavior` 加
  `lie_fail`（失败兜底触发）。开关**默认关**（灰度：先人工开着试 N 次）。
- **判据**：实机连续 3/5 次通过测谎；全程 `perf.log` 可复盘。

## 6. 风险表

| 风险 | 现状/预案 |
|---|---|
| 窗口模式尺度失配 | M1 已知 ✗；M3 多尺度一并做 |
| 指针加速非线性 | 闭环自校正 + 同状态标定（§4） |
| 6fps 素材 vs 实时流帧率差 | 回放器先量实际位移分布；实时流 fps 更高只会更容易 ✓ |
| 目标与干扰重叠/交叉 | 运动连续性关联 + 短暂遮挡容忍（丢失计数不清零立即重初始化） |
| 失败弹窗没见过 | captures 自愈闭环攒素材（M1 那套继续跑） |

## 7. 明确不做 / 暂不做

1. **不做绝对坐标鼠标**（固件 HID 相对移动是既定硬件路线，改它超出本题）；
2. **M2a 之前不训检测器**（先证明时序路线，避免两头开工 ✗）；
3. **断线重连**：按用户口径**暂时不处理**（先做防掉线/测谎），已有部分逻辑在
   `docs/断线重连设计.md`。

## 8. 追踪器实时口径（迭代记录）

细节散在 `perception/lie_tracker.py` 的注释与 `tools/selftest_lie_*.py` 里；这里只记**跨会话必须知道**的几条：

- **每个检出框的身份（`_box_identity`，用户 2026-10-01 定稿）**：拿**上板**登记的假目标当参照，
  覆盖率过 `0.75` 之后按**面积倍率**（框 / 假框）分：
  **≤1.7 ⇒「假目标」**（检出框又检出了假目标 ⇒ **不许锁红** ✗ ⇒ 该帧红框消失、进预测态）；
  **>1.7 ⇒「融合信号」**（大框直接包住假目标 ⇒ 给红框且判 `merged` ✓）。
  ⚠ 白块观测落在框里时**免判**（开局目标白块恰好压在一块已上板的砖上 ⇒ 免判才不抹掉开局红框 ✓）。
  ⚠ 阈值边界（1.7）夹在用户点名的两组实测数之间（帧 31 倍率 1.55 该消失 / 帧 27 倍率 1.87 是并集）✓。
- **白箭头（`vel_rel`）与圆心（用户 2026-10-01 定稿）**：白箭头 = **圆心自己的曲线预测**
  （`_path_pred`：切向 + 曲率 ✓）**再按设计旋转到"假目标群速度的反向"**；**圆心严格按白箭头走**
  （"无观测"分支的步长 = `_vel`，不再用没旋转的曲线预测 ✗）。
  **契约**：**没有红框**的拍，`vel_rel × dt` = **下一帧圆心相对假目标群的位移** ✓
  （有红框 ⇒ 圆心被"吸附"修正 ⇒ 允许偏 ✓）。⚠ 白箭头**不许取检测框的速度** ✗（框是假目标）。
  实现要点：覆盖点必须在 `process()` **最末**（`_sep_takeover` 之后、`_anti_group_vel` 之前 ✓）——
  放中间会被"对角修正 EMA / 平滑接管 / 框速度"逐拍盖掉 ✗。实测无红框拍误差：12.1→**3.4px**（9月30日(1)）/
  16.8→**2.1px**（10月1日）。
- **分离那一拍（`_merge_split`）**：红框塌缩成"假目标自己那格" ⇒ 这一拍
  ①**不夹取**、绿圈按预测走（用户 R42："任何情况下，都不允许将绿圈往预测方向的反方向跑"）；
  ②**不对外报红框**（`out["tbox"]=None` ⇒ 演示窗红框消失、进淡粉色**预测态**，用户 R22 口径）；
  ③ 统一出口的硬下限在这拍也不夹。⚠ **与"绿圈必须内接红框"（`selftest_lie_demo` 第 ⑦ 条）
  在这一拍不可兼得** ⇒ 判据用"红框消失"消解，别试图两全 ✗。
- ⚠ **代价**：报告位置会**反过来决定选哪格红框** ⇒ 任何改动一旦落到 `self.pos`/`_raw`，
  **整条轨迹必在第一次分离处分岔** ✗；合成台（有真值）**判不了**这类改动（改前改后逐位一致）。
  要判只能**看演示窗**（`tools/lie_demo.py`）。
- **只改"报告位置"的那类修正**（例：并集吞下在册假目标 ⇒ 圆修正到对角）必须
  **在 `self.pos`/`_raw` 写完之后**做，否则会经选框反过来改掉整条轨迹 ✗（A/B 实测过）。
- **诊断入口**：`tools/lie_demo.py`（演示窗）/ `tools/eval_lie.py --synth N`（合成台，有真值）/
  `tools/lie_replay.py`（离线回放）。临时探针用完请删（`tools/_probe_*.py` 一律不留 ✗）。

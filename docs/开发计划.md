    ⇒ **整条都不下发**并说清第几步（半途停在上不去的平台比不下更糟）。

    设想的 `set_name → [job, ...]` 表：路径起点是"我现在站哪个集合"，每一刻都可能变 ✗；

    与「命令前往」**同一处**。

### T4. `selftest_decision` **偶发**原生崩溃（访问违例 0xC0000005）

- **现象**：跑全套回归时，`tools/selftest_decision` 偶尔以 `EXIT=-1073741819`
  （访问违例）退出，**同一命令重跑就全过**（37/37）。单独跑它时也基本不崩。
- **判断**：套件里有几处会建 `QApplication` / 窗口（离屏）⇒ 像是 **Qt 析构和 GC 抢时序**
  的偶发崩溃（仓库里为这类"无征兆闪退"留过注释：接收线程和 Qt 主线程抢析构）。
  **不是**某条断言的逻辑失败（崩的那一刻没有任何 `[NG]`）。
- **实测复现率**（2026-09-26 抽样）：单独连跑 5 次崩 1 次；再连跑 3 次崩 1 次
  ⇒ 大约 **1/3 ~ 1/5**。两次崩的现场都是**没有任何 `[NG]`**（用例全过、进程没了）
  ⇒ 更像时序 / 析构问题，不是某条断言失败。
- **要做什么**：① 连跑 20~50 次统计复现率；② 若确实集中在 Qt 对象销毁，给这些用例
  加显式的对象生命周期管理（用完 `deleteLater` / 显式 `del` + `gc.collect`），
  或者把"必须建窗口"的用例挪进单独的进程跑；③ 崩了要能自证是"环境/时序"而不是逻辑
  ⇒ 输出里补一句"进程在用例 X 之后消失"。

# 防掉线（anti-AFK）设计

**这份文档只写"契约"**：状态机长什么样、每个状态谁维护、失败怎么办、和别的模块怎么划界。
代码在 `decision/agent.py`（状态机）与 `gui/player_panel.py`（参数与显示）。

> 为什么单开一份：这些不变式以前全散在代码注释里，结果 2026-09-26 连着踩了两个坑
> （"定点休息进来之后界面写「未休息」"、"实时页一行都不显示"）—— 都是**同一类**：
> 一个状态要在好几处各登记一次的契约，漏一处就**静默说反话** ✗。

---

## 1. 两个类型

| id | 显示名 | 干什么 |
|---|---|---|
| `hidden_rest` | 隐身休息 | 演「进入隐身序列」→ 等**通用休息时长** → 演「退出隐身序列」 |
| `spot_rest` | 定点休息 | 走到**指定地点** → 演「到达后行为」→ 等**通用休息时长** → 非空就走到「结束后前往」 → 回战斗 |

两型共用**触发时间**（随机 `[下限, 上限]` 分钟）、**通用休息时长**（随机区间）、
「被打断后重试(s)」「被打断重试」开关。**换类型不重排计时**（用例钉着）。

---

## 2. 状态机的唯一契约表

`decision/agent.py` 的 `REST_STATE_SPEC` 是**唯一真源**，其余全部派生：

| 状态 | 文案（界面共用） | spot | timed（有剩余时间） | interrupt（补血算打断） |
|---|---|---|---|---|
| `afk_enter`     | 进入隐身…   | ✗ | ✓ | ✓ |
| `afk_rest`      | 休息中      | ✗ | ✓ | ✓ |
| `afk_exit`      | 退出隐身…   | ✗ | ✗ | ✗ |
| `afk_spot_walk` | 前往休息点… | ✓ | ✗ | ✓ |
| `afk_spot_act`  | 到达后行为… | ✓ | ✗ | ✓ |
| `afk_spot_rest` | 定点休息中  | ✓ | ✓ | ✓ |
| `afk_spot_back` | 结束后前往… | ✓ | ✗ | ✗ |

派生出来的（**别再手写第二份** ✗）：

```
REST_STATES           主 tick 靠它决定"这一拍走休息分支"
SPOT_STATES           手动结束 / 被打断时，定点那型不走 afk_exit（它身上没有隐身）
REST_STATES_TIMED     发布 rest_until_monotonic 时按它过滤
REST_STATES_INTERRUPT 补血算"被打断"的阶段
rest_state_text(st)   两个面板（玩家面板卡片 / 实时页计时任务）**共用**
```

**加新休息类型的检查单**（只有两处）：

1. 往 `REST_STATE_SPEC` 加一行；
2. 在 `_begin_rest` 里给这个类型一个入口（选一个起始状态）+ 在 `_run_rest` 里给它阶段。

其余（界面文字 / 分发 / 倒计时 / 打断）都是派生的 ✓。用例
`t_rest_state_text_covers_all_states` 会遍历整张表检查"每个状态都有话说" ✓。

## 3. 谁发布、谁清理

- **发布**：`_run_rest` 的**尾巴**统一发布 `settings.rest_state`（`""` 或某个 `afk_*`）
  与 `rest_until_monotonic`（只有 `REST_STATES_TIMED` 那几个）✓。
  ⚠ 阶段推进在 `_run_rest_spot` 里做，但**发布在 `_run_rest`** —— 谁绕过 `_run_rest`
  直接调 `_run_rest_spot`，界面就会一直显示上一个状态（写文档时踩过 ✗）。
- **清理**：`_finish_rest` 兜底收尾（见下）；停自动的分支由 tick 负责（它也清
  `rest_state` / `rest_pending` / `next_afk_monotonic` ✓）。
- **按键**：休息各阶段按的键记在 `_afk_ctx` 里；`_finish_rest` **自己也会松一次**
  （不指望每个调用点都记得 ✗）。

---

## 4. `_finish_rest` 的兜底契约（收尾必须幂等、必须干净）

1. 松开 `_afk_ctx` 里还按着的键、清掉上下文（**自保**：任何调用点忘了都不该卡键 ✗）；
2. 清 `_spot_started`（不然下一轮"还没出发"会被当成"走完了" ✗）；
3. **收掉属于休息的那条路线**：`_route_why` 以「定点休息」开头才 `stop_route` ✓ ——
   用户自己下的「命令前往」**不许**被休息结束连坐 ✗（它"挂上就是授权，一路做到位"）；
4. 状态复位（`state=idle` / `rest_until=0` / `rest_state=""` / `rest_pending=False`）、
   重置朝向与"找不到玩家"的计时（否则休息一超时就撞上朝向超时会直接停自动 ✗）；
5. 排下一次触发（被打断过 ⇒ 按 `anti_afk_retry_sec` 秒，否则随机 `[下限,上限]` 分钟）
   并**立刻**发布 `next_afk_monotonic`（界面马上能显示倒计时 ✓）；
6. **点亮「临时战斗」**（`_temp_fight = True`，用户 2026-09-27 要求）：收工/被打断之后
   那段回战斗的路，**有怪就先打** —— 不受「限制战斗区域」约束 ✓（休息点多半不在战斗
   区域里，而"被打断"本身就说明有东西正在打我们；老行为是一路不还手地往回走 ✗）。
   熄灭见 `decision/agent.py` 里 tick 那一支：**这一波打完了**（视野里没得打了）就关 ✓
   —— 不用时长，所以没有常数 ✓。

## 5. 失败语义（一律"如实说"，不许硬走、不许静默）

| 情况 | 行为 |
|---|---|
| 定点休息：路径解析不出来 / 半路断了 | 记一句（`_rest_note`，画面上那行）+ **回战斗** ✗ 不许硬走 + ⭐ **按「被打断」处理**：下次休息排到 `anti_afk_retry_sec` **秒**之后（用户 2026-09-28 要求 ✓） |

### ⭐ 「休息过程中循环行为」（用户 2026-09-28 要求 ✓）

「定点休息」还有**两个**行为序列，别混：

| 项 | 什么时候跑 | 跑几次 |
|---|---|---|
| **到达后行为**（`anti_afk_spot_seq`） | 走到地方**之后、开始歇之前**（`afk_spot_act`） | **一次** |
| ⭐ **循环行为**（`anti_afk_spot_loop_items`） | **休息中**（`afk_spot_rest`） | **按 `anti_afk_spot_loop_min/max`（秒）循环** ✓ |

⭐ **循环行为是一个"列表配置"**（用户 2026-09-28 升级 ✓ 原话："把循环行为编辑做成列表配置，
行为编辑器里点击确定后，向列表里加一项，每项可以**重命名**、**删除**、**双击打开行为编辑器**
编辑。实际的执行**每个循环里会按照每个项目依次执行**"）：

- 数据：`anti_afk_spot_loop_items = [{"name": 名字, "seq": 一段行为}, …]` ✓
  —— ⚠ **老配置**（"一段序列"那种 `anti_afk_spot_loop_seq`）在 `from_dict` 里**自动包成一项**
  （名字「循环行为」✓）⇒ **用户已配好的东西不丢** ✓；
- **一次"循环" = 依次跑完列表每一项**（项与项之间**不等间隔** ✓ "依次"就是这个意思 ✓），
  整轮跑完才等 `anti_afk_spot_loop_min/max` 秒 ✓（间隔从**演完**那一刻起算 ✓）；
- 界面（`gui/player_panel.py`）：列表 + `添加 / 重命名 / 删除 / 上移 / 下移`，
  **双击一行 = 打开行为编辑器** ✓（用户指定的手势 ✓）；**上移/下移 = 执行顺序** ✓；
- ⚠ 空序列的项**跳过**（允许先建空项 ✓ 跳过比卡住好 ✓）。

⭐⭐ **「休息结束推迟到循环执行完」**（`anti_afk_spot_loop_hold`，用户 2026-09-28 要求 ✓
原话："勾上休息过程中循环行为时，再加一个开关子参数『休息结束推迟到循环执行完』"）：

- 界面在「循环时间(s)」**下面**、同一块缩进里 ⇒ 只有勾了「休息过程中循环行为」才看得见 ✓
  （它本来就是那一块的**子参数** ✓）；
- **不勾**（默认）= 休息**到点** ⇒ 循环**当场收摊**（`_stop_spot_loop` 掐断 + 松键 ✓ 老行为 ✓）；
- **勾上** = 到点、而**这一轮还在演** ⇒ **先不结束休息**，等它把**这一轮**演完再结束 ✓
  （⚠ 期间**不许再开新一轮** —— 见 `_hold_rest_for_loop` 里 `_loop_hold` 的作用 ✓）；
- **为什么需要它**：到点时那一轮可能**才演到一半**，直接转「结束后前往」就成了"一边按着
  循环的键、一边下发寻路的键" ⇒ **两边打架** ✗；
- ⚠ 只管"**自然到点**"这一条 —— **手动结束**走另一条（见下 ✓）。

### ⭐ 「手动结束休息」≠ 立刻掐断循环（用户 2026-09-28 ✓）

用户口径："**结束休息不应该打断正在进行的循环**" ✓。定点那型点「结束休息」时：

- 手上**没有**在演 ⇒ 停路线 + **立刻收尾** ✓（不傻等 ✓）；
- 手上**正演着** ⇒ 转成"**收尾中**"（`_rest_stop_pending`：留在 `afk_spot_rest` 里把它推完，
  同时 `_loop_drain` ⇒ **不再起跑下一项** ✓），**演完那一拍**才停路线 + 收尾 ✓；
- ⭐ **收尾与"自然到点"是同一份**（`_end_spot_rest` ✓）：配了「结束后前往」⇒ **去那儿** ✓；
  没配 ⇒ 直接回战斗 ✓。
  ⚠⚠ 手动结束原来**跳过**了「结束后前往」整格（用户 2026-09-28 报："我点手动结束休息后，
  **没有收到寻路任务**"✗）——"**休息结束**"在用户心里是**一件事**，不该因为"是点按钮停的"
  就少做一步 ✓。

⚠⚠ **为什么必须"留在休息状态里等"**（踩过 ✗）：原来那套是"立刻收工、让 `_loop_drain_beat`
在**后台**把它推完" —— 可回战斗之后只要**没怪**，"平地巡逻无怪 idle"那条就会**每拍**调
`_release_combat_keys()` ⇒ `_stop_spot_loop()` ⇒ 手上那一段**当场被掐断** ✗（而且**不留痕**，
极难查 ✓）。⇒ **要"演完"，就必须留在休息状态里等** ✓。
⚠ 安全网那一侧**不许**为这条改成"演完再收"：停自动 / 关防掉线 / 切项目仍然**立刻松键** ✓。

⭐ **"每个循环项目的当前状态"看得见**（用户 2026-09-28 追加 ✓："休息过程中希望能看到每一个
循环项目的当前状态信息"）—— 运行态走 `settings` 那套**只读镜像**（同 `fight_zone_name` ✓
**不进 `to_dict`** ✓）：

| 字段 | 含义 |
|---|---|
| `spot_loop_total` / `spot_loop_idx` | 有效项总数 / 正在演**第几项（1 基** ✓ `0` = 没在演 ✓） |
| `spot_loop_name` | 正在演那一项的**名字** ✓ |
| `spot_loop_next_at` | 下一轮起跑的**绝对时刻**（`time.monotonic()` ✓ 与界面同钟 ✓ `0` = 没在等 ✓） |

- 界面（`PlayerPanel`）**两处**显示：
  · **休息状态那行**：`定点休息中·循环 2/3「起身」`；一轮跑完在等 ⇒ `循环一轮完成，12 秒后重来` ✓
    （由 `_rest_text` 拼 ✓ 只在 `afk_spot_rest` 阶段显示 ✓）；
  · **列表里当前那一项**加 `▶` 前缀（挂在 500ms 的 `_state_timer` 里刷 ✓ 不另开定时器 ✓）。
- ⚠⚠ **`▶` 只在休息中显示**、且**只改文本、不动选中行**（用户正拿这个列表编辑 ✓
  抢走选中、或重灌列表把选中清掉都会很难受 ✗）；
- ⚠ `_stop_spot_loop` 里要**把运行态一起清掉**（不然停休息之后界面还挂着"循环 2/3「起身」" ✗）。

- **开关** `anti_afk_spot_loop`（默认 **关** ⇒ 老行为一字不变 ✓）；
- ⚠ **它与 `custom_timers` 无关** —— 那套会被 `_pause_timers` 在休息期间**冻住** ✗，
  而这条的本意就是"休息时该做的动作别停" ✓ ⇒ 自持 `_loop_ctx` / `_loop_next_ts`
  （范式照抄 `_custom_timers` 的"到点起跑 ⇒ 跑完排下次" ✓）；
- ⚠ **间隔从"演完"那一刻起算**（不是"起跑"✗）—— 序列自身占的时间不该白算进间隔 ✓；
- ⚠⚠ **收摊要松键**（循环序列也是"按着的键"的宿主 ⇒ 漏一处就**卡着键继续走** ✗）——
  ⚠ 但**别逐处去加** ✗：会离开这个状态的路有**十几条**（全文件 `_afk_ctx = None` 就有 **16 处** ✓），
  逐处加必然漏 ✓。收在**两个汇合点**上：
  | 汇合点 | 覆盖什么 |
  |---|---|
  | **`_release_combat_keys`** | "松所有相关键"的**总入口**：停自动 / 关防掉线 / 切项目… ✓ |
  | **`_run_rest` 入口兜底**（`state != "afk_spot_rest"` ⇒ 收） | **任何**让状态离开"休息中"的路 ✓ |

- ⭐⭐ **"结束休息"与"循环"的关系**（⚠ 用户 2026-09-28 **改过主意两次**，**以这段为准**）：
  - **上一版**（已废 ✗）："结束休息要**杀掉**循环正在执行的动作 + 终止循环" —— 立刻掐断 + 松键；
  - **现行版** ✓：**"结束休息不应该打断正在进行的循环"** ⇒ **手上那一段继续演完**（**键不松**✗），
    但**不再开始新的一项 / 新的一轮**，**演完那一刻**才收摊 ✓。
  - 实现：`_loop_drain`（"演完就收"）+ `_drain_spot_loop()`（结束休息时的收法：在演 ⇒ 只置标记；
    没在演 ⇒ 直接收）+ ⚠⚠ **`_loop_drain_beat` 必须挂在主 tick 的每拍公共路上** ✓ ——
    因为休息一结束 `_spot_loop_beat` 就再不会被调 ⇒ 没人推的话手上那段（**还按着键**）
    会**永远挂着、键也松不掉** ✗。
  - ⚠ **"立刻杀"仍然存在，但只归另一条路**：**停自动 / 关防掉线 / 切项目**
    （`_release_combat_keys` ✓）—— 那是"**立刻停**"、不是"演完手上这段"⇒ **别互相替代** ✗；
- ⚠ 用例挑场景时**必须挑"不走 `_finish_rest`"的那条**（换类型到 `afk_enter` ✓）——
  挑 `afk_spot_back`（"结束后前往"）会被 `_finish_rest` 兜住 ⇒ **即使兜底被删也照样收**

## 6. 和别的模块怎么划界

- ⚠ **前提：tick 里的第一条总判据是「有怪先打」**（完整说法见 `docs/寻路设计.md` 的
  "攻击优先"那一节）：只要**攻击范围内有怪**，这一拍就**只做「输出行为」**（attack / 规避）
  —— 不追怪、不走位、**进不了休息**（本模块要"等清怪" ✓）、**寻路任务也要让路** ✓。
  它是靠 tick 里的**顺序**成立的（`if in_range:` 排在休息/寻路/巡逻各分支之前 ✓），
  **不是开关** ⇒ **休息分支是早退的** ✓，所以"赶路期间有怪先打"得自己补
  （`_rest_travel_beat` ✓）。
  ⚠ **加任何新分支（新休息类型 / 新阶段 / 新早退路径）之前，先回来过一遍这条判据** ——
  它已经被漏过三次：休息赶路不还手 ✗、命令前往身后怪没人接 ✗、挂任务时走位毁掉对齐 ✗。
- **休息 ↔ 寻路：互相独立**（用户明确要求）：休息分支不判断寻路、寻路不判断休息，
  两边各按自己的时刻表走 ✓。
- **休息 ↔ 定时行为（自定义定时行为）**：默认休息期间计时器**冻住**（`_pause_timers`
  按增量把"下次触发时刻"往后推 ⇒ 休息途中关防掉线也不会算错 ✓）；**每条行为各自**带一个
  「休息时暂停计时」开关（数据里是 `pause_on_rest`，缺省 True = 冻住 ✓）—— 不勾的那条
  **照常倒数、休息期间也会到点照演** ✓（给"休息时也得按的键"用：喂宠 / 喊话 / 报点…）。
  休息中各演各的，**没有按键仲裁**（见下）。
- **清空指令通道后必须"恢复按键"**：寻路 / 宏都可能很长，中间被定期 RELEASEALL 或
  「重置指令通道」打断时，固件侧的键被一次性松了，而本机进度还在 ⇒ `_reassert_ctx`
  把该按着的键**重按回去**（进度与记录都保留，下次再清还能再补 ✓）。

## 7. 明确不做 / 暂不做（写清楚免得后人以为是漏了 ✗）

1. **多来源按键没有仲裁 —— 用户 2026-09-26 明确不做** ✓。
   休息序列 / 定时行为 / 寻路三方可能在同一拍按同一根键，一方 `up` 会踩掉另一方的
   `down`。**保持现状**：只保证"各自独立"（这是用户要的 ✓），冲突**不检测、不仲裁**。
   ⚠ 以后有人想加"按键优先级"前，先回来问 —— 那会改变这条已定的边界。
2. **"休息是否真的生效"不做自动校验 —— 用户 2026-09-26 明确不做** ✓。
   即：隐身没放出来 / 被怪打断时，程序照样等满休息时长，**不报警**。手头有现成信号
   （血量回升 / 检测框 / 位置不动）可以做，但**决定不做**。
3. **休息阶段名和战斗状态共用 `self.state`**（已知脆弱，**暂不重构** ✗）：
   `afk_*` 那几个阶段名就存在 `self.state` 里，而战斗那套也用它（`attack` / `chase` / …）。
   于是"赶路期间有怪先打"只能**借名字再还原**（`_rest_travel_beat`：存 `keep` → 改
   `attack` → 跑 `_attack_state`/`_output_actions` → **finally 还原** ✓）。
   ⚠ 谁要再往这条路上加东西，**必须**跟着还原 —— 名字被改掉 = 休息机器下一拍认不出自己
     = 这次休息**静默作废** ✗（比不打架还糟）。彻底的办法是把休息阶段拆到独立字段
     （`self._rest_phase`），**没做**。
4. **卡键看门狗只盯输出序列**（这条**没被否**，只是暂不动）：
   休息 / 定时序列按着的输出键不在它的判据里 —— 因为长 delay 期间按住输出键是
   **合法**的 ✓，一刀切会误杀 ✗。要扩面得先定义"哪些按住算正常"。
   （目前 `_afk_ctx` 那一类由 `_finish_rest` 的自保释放兜住 ✓。）

## 8. 打点（事后复盘用，`core/perf`）

`afk_interrupt`（补血打断）、`afk_start`、`afk_done`、`afk_give_up`、
`key_reassert`（清空通道后重按）、`key_stuck`（看门狗抓到的漏放）。
出事时先看 `perf.log` 这几个计数，再决定查哪一段。
（⚠ 2026-09-28 起这些打点**全在 `behavior.log`** —— `perf` 里不再有了 ✓ 见
`docs/行为打点设计.md` ✓。）

⭐ **2026-10-03 补（"被切"必须收口 + 必须看得见）**：用户现场报"我配置的进入隐身行为很长，
但好像没有完成，中间是不是被什么切断了？（可以看 log）"—— 查下来**看 log 也答不出来** ✗，
两个原因：

  · **会离开休息的早退路各自了事**：tick 开头那两条（`if not s.enabled` = 关自动、
    `ws.screen != "combat"` = 界面接管）以前直接 `_set_state("idle")` ✗ ⇒ 休息的账
    （`_afk_ctx` 半截序列 / `rest_state` / **下次休息的排期**）没结清、`afk_done` 也不打 ✗；
  · **`afk_done` 分不出被切还是完成**（`afk_give_up`/补血打断那几条**被切也照样打它** ✗）。

⇒ 现在：这两条早退（以及 `shutdown`）一律走 **`CombatAgent._cut_rest(now, why)`**（**唯一收口** ✓）：
打 `afk_cut`（含 `why` ✓）+ `_finish_rest(why=…)`；`afk_done` 加 `why` / `phase` / **`hidden`**
（收工时还停在进入 / 休息相 ⇒ **隐身可能还开着** ✓，同时写到画面那行 ✓ 不再静默 ✗）；
"进入序列被到点丢掉"那条另打 `afk_enter_dropped`（`played_s` / `rest_s` ✓）。

⚠ **别顺手改成"被切时也演一遍退出隐身"** ✗：这两条路恰恰都**不能按键** —— "关自动"= 人要求
停手、"界面接管"= 人根本不在游戏里（登录 / 频道 / 测谎 ⇒ 按键会乱按 ✗）。真需要演退出的
（**手动结束休息 / 休息到点**）走的是另外两条路 ✓（见 `_run_rest` 与 `rest_abort` 那段 ✓）。
真实后果（"隐身可能还开着"）由 `hidden=1` **如实记下来**，不假装它关掉了 ✓。

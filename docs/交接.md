## 4. 当前状态（已实测确认）

### 数据流

```
YOLO检出框 → 群体基准(中位 + EMA) → 判据(v_rel → dev → score) → 关联(两轮配对)
   → 滤波(KF@相对群体坐标) → 质量自检(q / m / ma) → 异常处置(断掉 + 沿预测滑)
   → 身份切换(分数 + 迟滞；跟丢时余量归零) → 报告位置 pos
   → 鼠标控制律(LieMouseController：P控制 + 前馈 + 死区 + 限幅)
```

### 实测指标（`10月1日` 全片 70 拍）

| 指标 | 值 |
|---|---|
| 目标换人次数 | **0 次**（此前是 14 次，平均每 5 拍换一次）|
| 框状态分布 | 正常 53.8% ｜ 融合 3.8% ｜ 可疑 3.5% ｜ 残缺 38.9% |
| 标准面积 | 22419（边长 ≈ 150）|

### 三个正交的"维度"（别混）

| 维度 | 谁回答 | 量 |
|---|---|---|
| **这一格的数据能不能信**（测量质量）| 匹配分 `m` / 面积可信度 `ma` | 距离因子 × 面积因子 |
| **它是不是真目标**（身份）| `dev` / `v_rel` / `q` | 相对群体偏了多少 |
| **它算到哪个编号头上**（归属）| `box_v` 里的 `tid` | 配对结果 |

⚠ `m` 高**不代表**它是真目标 —— 一个**假目标**的框同样可以又干净又准，`m` 照样 1.00。

### 关键常量（都在 `lie_motion.py` 顶部，已核对过当前值）

| 常量 | 值 | 含义 |
|---|---|---|
| `_PAIR_GATE` | `70.0` | 配对门限（离预测超过这么多 px ⇒ 配不上）|
| `_SWITCH_MARGIN` | `8.0` | 换目标需要的分数余量（迟滞）|
| `_VEL_DECAY` | `0.96` | 滑行期速度衰减（每拍乘一次）|
| `_STUCK_RATIO` | `1.40` | 面积超过基准这么多 ⇒ 判定「融合」|
| `_SMALL_RATIO` | `0.75` | 面积低于基准这么多 ⇒ 判定「残缺」|
| `_AREA_EDGE` | `2.0` | 判定「框贴边」的边界容差 |
| `_M_OK` | `0.70` | 面积可信度高于它 ⇒ 权重照旧（不降权）|
| `_M_SUS` | `0.50` | 低于它 ⇒ 记一次"不可信" |
| `_SUS_NEED` | `2` | 连续这么多拍不可信 ⇒ **权重归零 + 停喂 KF** |

## 5. 已经修过的坑（**别重新踩**）

1. **`_t.pred` 在粘连/冷却期必须含 `vr`**（`_t.obs + 相机 + vr`）。
   只加相机 ⇒ 位置相对群体**原地不动** ⇒ 画面上"真目标不前进"。
   ⚠ 三处"滑行"（粘连期 / 没配上 / `MotionRunner`）**口径必须一致**。
2. **"断掉采信"不等于"冻结"**：位置要**沿预测滑**（走"没配上"那条路），不能原地不动
   （曾实测卡死 7 拍）。
3. **换目标时 `pos` 要重置**（`self.pos = None`），但 **`claim`（滑行后认领）时不许清**
   （用户要"别瞬移"）。曾实测差 541px 持续 5 拍。
4. **`rel`（相对轨迹）的推进在 ③ 段做**，粘连期那一支**也已覆盖** ⇒ **别在别处重复加**
   （会变成每拍两倍，实测融合期每拍涨 63 vs 正常 31）。
5. **`box_v` 的坐标用「框自己的中心」**（YOLO 给的那个），不是 `_t.obs`
   （后者滞后一拍 ⇒ 全部框显示"未配对"、标签画偏 22px）。
6. **`std_area`（标准面积）口径**：**全历史 + 每拍重判**，只收「**不贴边 && 非融合**」的框。
   - 贴边的框（被画面切掉的"半个目标"）实测占 **55.1%** ⇒ 会把基准**拉低 45%**
     ⇒ 面积倍数**虚高** ⇒ **大量正常框被误判成"融合"**。
   - "非融合"这个判据**依赖基准本身** ⇒ 必须**每拍拿当前基准对全部历史重判**（= "历史追溯"）。
7. **`_show_layers()` 里的开关是正交的**，别互相耦合：`boxes`（框+蓝箭头）/ `box_id`（编号标签）
   / `cands`（候选圈+分数）/ `rel_tgt`（真目标轨迹）/ `rel_mouse`（鼠标轨迹）/ `panel`（HUD+图例）
   —— 注意**"编号标签"出现在三处**（框中间那行、"睡着"的 `#N 推的`、候选圈旁的 `#N`），
   改 `box_id` 时三处都要管。

## 6. 下一步任务：用「融合框的变化」指导报告位置

### 现状（先自己验证一遍，别直接信）

- **融合期**（面积 > 基准 × 1.40，或**部分重叠** 1.15~1.33x）⇒ **框心 = 两个目标的中点**。
- 现在对这类框的处置：**位置权重归零 + 停止喂 KF + 沿预测滑**（见 `_M_OK` / `_SUS_NEED` 那段）。
  ⇒ 也就是说：**彻底丢弃了融合框携带的信息**。
- 而"沿预测滑"是**匀速直线**（KF 常速 + `vr` 衰减到 0）。

### 可用的信息（这才是要做的地方）

1. **框面积在变大 / 变小** ⇒ 两个目标在**靠近 / 远离** ⇒ 可反推各自沿连线方向的运动分量。
2. **框心的移动**（即使**绝对值**不可信，**变化量**可能仍有信息）。
3. ⚠ **现成但完全没接的资源**：`dir_conf`（方向置信度，`_dir_votes()` 算的）
   —— 来自**框四条边的几何运动**，**不依赖配对**，目前**只用来画灰箭头**，没参与任何决策。
   它可能是"长滑行期该往哪走"的更好来源。

### ⭐⭐⭐ 关键：**只有「含真目标的」融合框才有用**（用户 2026-10-04 给的几何判据）

用户原话：「**不跟真目标圆相交的检出框肯定不是融合紫框**」✓

**实测（`10月1日` 全片）**：紫框共 **42** 个 ——

| | 个数 | 占比 |
|---|---|---|
| 与真目标圆**相交** ✓ | 32 | 76.2% |
| **不相交** ✗（离圆边缘中位 **42 px**、最大 58 px）| **10** | **23.8%** |

⇒ 那 10 个是**两个别的目标**重合，**跟真目标无关** ✗ ⇒ 它们**提供不了真目标的任何信息**。

⚠⚠ **但注意语义，别改错地方** ✗：
- `stuck`（面积 > 基准 × 1.40）的本意是「**这条轨迹跟别人融在一起了**」✓
  ⇒ 对**任何**轨迹都成立（假目标之间重合也会触发 ✓）⇒ **"不采信框心"那条逻辑要保留** ✗
  （因为这时框心确实是**两个目标的中点** ✗ 对谁都一样 ✓）；
- 而「**紫框**」这个**显示**的含义该收窄成「**真目标被融合**」✓
  ⇒ 所以这是**显示语义**的事，**不是** `stuck` 的事。

✅ **已落地（用户 2026-10-04 选了 (b)：做进算法）**：

| 是什么 | 在哪 | 语义 |
|---|---|---|
| `_Track.has_tgt`（新字段 ✓）| `perception/lie_motion.py` | `True` = 这个框里**确实裹着真目标** ⇒ 它的面积变化 / 框心移动**携带真目标信息** ✓；`False` = 框里是**两个别的目标** ✗ |
| `box_v[8]`（第 9 位 ✓）| 同上 | 同一个值，给演示窗画框用 ✓ |
| `tracks[].has_tgt` | 同上 | 同一个值，给点选信息 / 诊断用 ✓ |

判定逻辑（`process` 的 ③ 段，紧挨 `_t.ma` 之后）：
```
① 它自己就是当前选中目标 ⇒ True（框本来就是它的，不用算几何）
② 别人 ⇒ 圆↔矩形相交判定：圆心到矩形最近点 <= 半径
⚠ 用的是「上一拍的选中目标」（self.tid，因为这一段跑在"⑥ 选目标"之前）
⚠ self.tid is None（还没选上）⇒ 一律 False（无从判断，别猜）
```

演示窗已同步：**洋红 = 含真目标的融合** ✓ ／**暗紫 = 融合但跟真目标无关** ✗
（图例和点选信息都写明了 ✓）。

⚠ 实测口径差异（**别当成 bug** ✓）：用真实框的 w/h 判定 ⇒ 得 **28/42 = 66.7%**；
用"标准面积推的近似半宽"手算 ⇒ 得 32/42 = 76.2%。**实现用的是真实框尺寸 ⇒ 以它为准** ✓。

## 8. 界面上几个容易看错的东西（用户会问）

| 画面元素 | 含义 |
|---|---|
| 绿圈 / 十字 | **报告位置 `pos`**（算法认为目标在哪）|
| 白圈 + 实心点 | **模拟鼠标**（光标）|
| 橙粗线 | **真目标**那条「相对群体」轨迹（判据本体）|
| 暗黄细线 | **鼠标**那条「相对群体」轨迹（结果指标）|
| 紫 / 洋红框 | **融合**（框心 = 两目标中点 ⇒ 位置不采信）|
| 橙黄框 | **可疑**（匹配分低 ⇒ 已降权）|
| 小灰框（无标签）| **残缺**（框只剩一小块 ⇒ 框心是碎片重心）|
| 标准大小灰框 + `#N 推的` | 这一拍**没有检测框**，位置是**推**的 |
| 一圈辐射状灰箭头 | **方向置信度** `dir_conf`（越亮越长 = 该方向越有依据）|

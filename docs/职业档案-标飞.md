# 职业档案 · 标飞（草案 v1 · 2026-10-11）

> 目的：把「**标飞**」这个职业的**能力与权重**收成**一份数据** ✓ —— 而不是在
> `decision/agent.py` 里再加一串 `if strategy == "标飞"` ✗。
>
> 用户 2026-10-11 ✓ 原话（需求来源）：
> 1. **近距离有怪挥拳几乎 0 输出** —— 必须保持距离；
> 2. **跳可以「舍近求远打怪」** —— 跳到远处那只，一下带进攻击框；
> 3. **需要频繁评估最佳输出位置并前往** —— 不是定时/规则，而是按**输出效率**选点。

---

## 一、三层分工（**别混** ✗ —— 这是本档存在的前提）

| 层 | 回答什么 | 住哪儿 | 谁改 |
|---|---|---|---|
| **地图事实** | 哪些平台、谁连着谁、跳一下要多久 | `datasets/map/<id>.zones.json`（`core/zones.py` / `mapdata.py`） | 路线识别编辑器 |
| **区域配置** | **这块平台允不允许打**、打完去哪 | 项目里的 `battle_zones`（`can_fight` / `fight_dst` / `fight_max_s`） | 玩家面板 |
| **职业档案**（本档） | **这个角色**打得到多远、跳过去值不值、各种折扣 | `profiles/<职业>.yaml`（**新增** ✓ 代码落点 `decision/engage.py`） | 标定 + 调参 |

⚠ 现在这三样**混在 `battle_zones` 一项里** ✓（有效距离带就和"这块平台能不能打"写在了一起 ✗）
—— **加第二个职业就会开始打架** ✗（同一块平台，标飞打得到、别的职业打不到 ✓）。
⇒ 本档就是把"**角色能力**"那一半分出来 ✓。

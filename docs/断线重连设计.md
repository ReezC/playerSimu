# 断线自动重连 — 开发文档

> 状态：**一期「界面判别」已落地**（`perception/ui_state.py` + 模板 + 离线验证通过）。
> 鼠标定位（§6.1）和重连状态机还没动。
>
> 素材：`datasets/records/断线重连素材.mp4`（1920×1080 / 60fps / 27.0s / 1622 帧）
>
> 本文里的像素坐标：**锚点坐标已按实测校准**（见 §6.3），其余仍是估算值。

---

## 1. 目标

自动打怪过程中断线后，机器自己能走完「登录 → 选服务器 → 选频道 → 选角色 → 进游戏」，
回到可打怪状态，不需要人工介入。

**不在本期范围**：

- 「进错频道」的补救 —— **当前哪个频道都能进**，所以不要求命中指定频道
- 多开 / 换角色 / 换服务器

## 3. 关键结论（决定方案走向）

### 3.1 「选择频道」界面不能用键盘操作 ← **用户实测确认**

← 这意味着**没有纯键盘退路，必须用鼠标**。这是本功能最大的技术门槛，
直接决定了下面第 6 节「鼠标绝对定位」是必须解决的，不是可选项。

### 3.2 不要求命中指定频道 → 精度要求很宽松

因为**哪个频道都能进**，所以：

- **不需要**精确点到「频道56」，只要点到频道列表里**任意一格**即可
- **不需要滚轮翻页**（第一页就有 20 个频道，随便点一个就行）→ 滚轮标定可以整个砍掉
- 频道格子约 `147 × 55`（1920 宽下），所以**光标误差 ±50px 都能命中**
- 服务器行 5 个横排，每个约 147px 宽，误差要求同量级

**这是本方案最重要的简化**：精度要求是「±50px 级」而不是「像素级」，
因此**不需要改固件做绝对坐标 HID**，用「撞角归零 + 标定走位」就够了（见 6.1）。

### 3.3 真正需要鼠标的只有 2 次点击

| 步骤 | 界面判据 | 动作 |
|------|---------|------|
| 1 | 提示框「与服务器连接发生错误」+「确定」 | `tap("enter")` |
| 2 | 「选择频道」标题出现 | 等服务器列表加载（12.0s 时还是空的） |
| 3 | 服务器行出现「蓝蜗牛」 | **鼠标：撞角归零 → 移到蓝蜗牛 → 左键点击** |
| 4 | 频道面板出现 | **鼠标：移到面板内某频道 → 左键点击** |
| 5 | 排队弹窗「排队者」 | 等它消失（长超时） |
| 6 | 「选择角色」 | `tap("enter")`（或点「开始游戏」） |
| 7 | 玩家框重新出现 | 完成，恢复自动 |

其余全是 Enter，现成能力。

## 5. 缺口

1. **没有界面判别**：完全不知道当前是登录 / 选频道 / 选角 / 排队
2. **没有重连状态机**：`agent.tick` 只在战斗态跑
3. **没有鼠标绝对定位**：`mouse_move` 只有相对位移，没有坐标目标、没有光标位置读回
4. **没有相关配置项**：`DecisionSettings` 里没有服务器坐标、超时、重试次数等
5. **没有断线判据**：只有「玩家框丢失」这一间接信号

## 6. 技术方案

### 6.1 鼠标定位（核心）—— 方案 A：撞角归零 + 标定走位（推荐）

`Mouse.move()` 是相对的，但可以利用**屏幕边界夹紧**造出绝对原点：

```
1) 发 MOVE -4000 -4000   → 光标被 OS 夹到 (0, 0)          ← 已知绝对原点
2) 按标定系数把目标客户区坐标换算成 Δ，发 MOVE dx dy
3) 左键点击
```

优点：不动固件、不需要读回光标位置；每次点击前都归零，**不会有累计漂移**。

**前提（必须做，否则坐标全是错的）**：

- 游戏机 Windows：指针速度固定 **6/11（默认档）**，**关闭「提高指针精确度」**
  （开启加速会让 count→px 变成非线性，映射立刻失效）
- 标定系数 `counts_per_px`（或反向的 `px_per_count`）

**标定工具（建议做成一次性脚本，放游戏机上跑）**：

```
循环：
  撞角归零 → 发 MOVE 固定的 (dx, dy) → 用 win32api.GetCursorPos() 读回真实落点
→ 自动算出系数，顺便验证线性度（多点采样，看偏差是否稳定）
```

比人工目测可靠得多，而且能顺手验证「加速是不是真关了」。

**误差预算**：需要 ±50px 级（见 3.2）。标定后如果残差在 ±20px 以内就很安全。

### 6.2 鼠标定位 —— 备选方案 B：改固件加绝对坐标 HID

让 Pro Micro 额外暴露一个 absolute pointing device，直接设定光标位置。

- 优点：精度最高、可重复、完全不受系统指针速度/加速影响
- 缺点：要改固件 + 处理 Windows 对绝对设备的识别

**当前不需要**（3.2 的精度要求用 A 就能满足），仅作为 A 走不通时的后路记录。

### 6.3 界面判别（模板锚点）—— ✅ 一期已实现

代码：`perception/ui_state.py`；模板图：`perception/ui_templates/*.png`；
生成/重生成：`python -m tools.make_ui_templates`（坐标表在 `ui_state.ANCHORS` 里）。

**已实现**（实测通过）：

| 界面 id | 锚点 | 实测（0.5 缩放下） |
|---------|------|------------------|
| `login_err` | `login_err_text` — 提示框「红圈图标 + 与服务器连接发生错误」那一条 | 真匹配 1.000 / 0.998，其余界面 ≤ 0.606 |
| `login` | `login_connect` — 木牌上的「连接」按钮 **(1085,505,135,70)**<br>`login_agree` — 木牌下「抵制不良游戏…」两行协议 **(965,602,425,36)** | 0.940 / 0.969，其余界面 ≤ 0.672 |

判定规则：**登记的全部锚点都命中**才算认这个界面（阈值 0.80）；
浮层优先（先 `login_err` 再 `login`）；都不命中返回 `None`。

**离线验证**（整段素材每 0.5 秒判一次）：

```
0.0s ~  2.5s  login_err      断线提示框
3.0s ~  3.0s  None           提示框淡出中
3.5s ~  5.0s  login          登录木牌可见
5.5s ~ 27.0s  None           连接中 / 选频道 / 选角 / 游戏内 —— 全程无误报
耗时 50 ms/次（0.5 缩放，3 个锚点）
```

#### 三个坑（都踩过，写下来免得重犯）

**1. 锚点不能含账号等用户数据。**
第一版拿整个登录木牌当锚点，里面带着账号 `15359879262` —— 换个账号就匹配不上。
锚点必须是「什么账号都一样」的元素。

**2. 看着很标志性的东西未必是界面独有的。**
CADPA 12+ 适龄提示框（右上角蓝框）第一版被当成登录界面的锚点，实测它在
12.5s（选频道）时分数仍是 **1.000** —— 它从登录一路跟到选角，不是登录独有。

**3. 「登录那段」其实是三个子状态，不是一块。**

| 时间段 | 画面 | 判据 |
|--------|------|------|
| 0 ~ 2.5s | 登录木牌 + **断线提示框** | `login_err` ✓ |
| 3.5 ~ 5.0s | **登录木牌可见**（等按「连接」） | `login` ✓ |
| 5.5 ~ 11.5s | **木牌已收起，只剩背景**（连接中） | **判不出来 → None** |

第三段是「按了 Enter（= 点了连接）之后、服务器还没响应」的过渡态，画面上
只有登录背景插画，没有任何独有 UI。**它和「在游戏里跑图」一样返回 None**，
所以 `detect()` 的 None 不能理解成「在游戏里」——上层必须靠别的信号区分。

对本期需求没影响：**断线后客户端会停在木牌可见的状态等用户按「连接」
（即 3.5~5.0s 那种），这正是要判的目标。**

#### 性能与分辨率

- 全分辨率（1920×1080）单个锚点要 **116.7 ms**，太慢；缩到 0.5 倍后 21 ms/锚点，
  三个锚点合计 **50 ms/次**。判别本来就是「每秒判一两次」用的，不需要每帧跑。
- 模板按 1920×1080 裁，判别时把整帧缩到基准的 `MATCH_SCALE`（0.5）倍再匹配 ——
  换分辨率不用重裁模板，前提是游戏 UI 随分辨率等比缩放。

#### 还没做的界面

| 界面 | 建议锚点（待裁） |
|------|----------------|
| 选择频道 | 左上「选择频道」标题；「蓝蜗牛」大标题区 |

| 选择角色 | 右侧「开始游戏」木牌；左侧「选择的 世界」 |
| 进入游戏 | 玩家框（现有 YOLO 的 `player` 类）出现 |

### 6.4 重连状态机

新建 `decision/reconnect.py`，纯状态机，不碰 Qt：

```
IDLE  ──触发──> 判别当前界面 ──> 按界面走对应动作 ──> 回到判别
```

规则：

- **每一步动作前必须先确认界面**（模板命中才动）—— 这是防「误点删除角色」的关键
- 每步有超时；超时则**重新判别**，而不是盲目继续
- 未知界面：等待 + 重试上限，超限则放弃并报警（不要乱点）
- 全部动作幂等：重复执行不会造成破坏

### 6.5 触发与接入点

现状（`decision/agent.py` 约 791-802 行）：

```python
if not ws.player.found:
    ...
    s.enabled = False        # 超时 → 直接停自动
    return {... "reason": "长时间未定位到玩家，已停止自动"}
```

改法：在这个分支里**先让重连状态机去看一眼界面**：

- 玩家框丢失超时 → 抓一帧 → `ui_state.detect()`
- 命中「断线提示框 / 选择频道」→ 进重连流程
- 没命中（只是玩家被遮挡）→ 维持现有行为

**不能只靠「玩家框丢失」触发** —— 被树挡住、走出视野也会丢失，必须用界面锚点二次确认。

### 6.6 排队弹窗

排队可能很久（素材里 11 名等了 2s，实际可能几十秒~几分钟）。
用**长超时 + 轮询**，不要当成失败重试。

## 7. 配置项设计（拟）

加在 `DecisionSettings` / `config/decision.json`：

| 字段 | 含义 |
|------|------|
| `reconnect_enabled` | 重连开关 |
| `reconnect_server_x` / `_y` | 目标服务器在**客户区**的比例坐标（如 `0.29 / 0.19`） |
| `reconnect_channel_x` / `_y` | 目标频道格的比例坐标（如 `0.33 / 0.36`） |
| `reconnect_mouse_scale` | 标定系数：1 个 count 对应多少像素 |
| `reconnect_step_timeout_ms` | 每步等待界面出现的超时 |
| `reconnect_queue_timeout_ms` | 排队弹窗专用超时（长） |
| `reconnect_max_retry` | 最大重试次数 |
| `reconnect_probe_after_lost_sec` | 玩家丢失多少秒后去抓帧确认是否断线 |

坐标存**比例**而不是像素 —— 分辨率/窗口尺寸变了自动适配（和 HP/MP 条同一套思路）。

## 9. 风险清单

| 风险 | 说明 | 对策 |
|------|------|------|
| **误点「删除角色」** | 选角界面三个按钮紧挨着 | 动作前必须模板确认界面；未知界面一律不动 |
| 点到「回到首页」 | 选频道界面左下有这个按钮 | 目标坐标要远离它；点击前确认界面 |
| 进错服务器 | 角色不在那个服务器（**频道无所谓，服务器可能不无所谓**） | 本期不做补救，靠坐标正确性保证；失败则重试 |
| 排队/爆满 | 排队要等；爆满频道可能进不去 | 长超时；失败重试（重新点一个频道） |
| 意外弹窗 | 任何一步都可能被弹窗挡住 | 状态机要有「未知界面」兜底 + 上限 |
| 指针加速 | 开了「提高指针精确度」→ 非线性 → 坐标全错 | 标定脚本里验证线性度；必要时提示用户改系统设置 |
| 流/画面来源 | 若游戏**客户端崩溃**（不是断线），画面会变桌面 | 判别不到任何界面 → 超时放弃并报警，不要乱点 |
| 反作弊 | — | **本功能反而是全项目最不敏感的部分**：走 Pro Micro 真实 HID，无注入标志 |

## 附录 A：重新抽帧（本文的坐标都靠它复核）

```python
# 顺序读取（不要用 set() + retrieve()，那样不推进帧号，会重复拿到同一帧）
import cv2
c = cv2.VideoCapture(r'datasets/records/断线重连素材.mp4')
fps = c.get(5)
want = {0.0, 1.0, 12.0, 15.0, 16.5, 18.0, 19.5, 24.0}   # 想要的时间点
i = 0
while True:
    ok, fr = c.read()
    if not ok:
        break
    t = i / fps
    for w in list(want):
        if abs(t - w) < 1 / fps / 2:
            cv2.imwrite('frames/f%05.1f.png' % t, fr)
            want.discard(w)
    i += 1
c.release()
```

裁模板时盯住这些区域（**坐标是估算值，需复核**）：

- 「选择频道」标题：约 `x 0.02~0.08, y 0.03~0.06`
- 服务器名行：约 `y 0.18`，第 1 个服务器约 `x 0.28`
- 频道面板：约 `x 0.30~0.60, y 0.32~0.58`
- 频道格子：约 `147 × 55` px（1920 宽下），面板内 4 列 × 5 行
- 「开始游戏」木牌：右下，约 `x 0.60~0.72, y 0.32~0.45`

**已复核确认**（重新抽 15.0s 帧放大核对）：

- 频道面板是 **4 列 × 5 行 = 20 个/页，行优先**

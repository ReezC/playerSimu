> 状态：**二期「断线判断 + 状态机」已落地**，界面锚点补齐（登录 / 选频道 / 排队 / 选角）。

## 1. 目标

自动打怪过程中断线后，机器自己能走完「登录 → 选服务器 → 选频道 → 选角色 → 进游戏」，
回到可打怪状态，不需要人工介入。

**不在本期范围**：

- 「进错频道」的补救 —— **当前哪个频道都能进**，所以不要求命中指定频道
- 多开 / 换角色 / 换服务器

## 3. 关键结论（决定方案走向）

### 3.1 「选择频道」界面不能用键盘操作 ← **用户实测确认**

← 这意味着**没有纯键盘退路，必须用鼠标**。这是本功能最大的技术门槛，
直接决定了下面第 6 节「鼠标绝对定位」是必须解决的，不是可选项。

### 3.2 不要求命中指定频道 → 精度要求很宽松

因为**哪个频道都能进**，所以：

- **不需要**精确点到「频道56」，只要点到频道列表里**任意一格**即可
- **不需要滚轮翻页**（第一页就有 20 个频道，随便点一个就行）→ 滚轮标定可以整个砍掉
- 频道格子约 `147 × 55`（1920 宽下），所以**光标误差 ±50px 都能命中**
- 服务器行 5 个横排，每个约 147px 宽，误差要求同量级

**这是本方案最重要的简化**：精度要求是「±50px 级」而不是「像素级」，
因此**不需要改固件做绝对坐标 HID**，用「撞角归零 + 标定走位」就够了（见 6.1）。

### 3.3 真正需要鼠标的只有 2 次点击

| 步骤 | 界面判据 | 动作 |
|------|---------|------|
| 1 | 提示框「与服务器连接发生错误」+「确定」 | `tap("enter")` |
| 2 | 「选择频道」标题出现 | 等服务器列表加载（12.0s 时还是空的） |
| 3 | 服务器行出现「蓝蜗牛」 | **鼠标：撞角归零 → 移到蓝蜗牛 → 左键点击** |
| 4 | 频道面板出现 | **鼠标：移到面板内某频道 → 左键点击** |
| 5 | 排队弹窗「排队者」 | 等它消失（长超时） |
| 6 | 「选择角色」 | `tap("enter")`（或点「开始游戏」） |
| 7 | 玩家框重新出现 | 完成，恢复自动 |

其余全是 Enter，现成能力。

## 6. 技术方案

### 6.1 鼠标定位（核心）—— 方案 A：撞角归零 + 标定走位（推荐）

`Mouse.move()` 是相对的，但可以利用**屏幕边界夹紧**造出绝对原点：

```
1) 发 MOVE -4000 -4000   → 光标被 OS 夹到 (0, 0)          ← 已知绝对原点
2) 按标定系数把目标客户区坐标换算成 Δ，发 MOVE dx dy
3) 左键点击
```

优点：不动固件、不需要读回光标位置；每次点击前都归零，**不会有累计漂移**。

> **注（已实现）**：`Mouse.move()` 的入参是 `signed char`（±127），原来固件直接把
> 4000 传给它是**截断**的（4000 → -96，方向都反）—— 也就是上面第 1 步的撞角归零
> 按原样根本走不到角上。现在固件里加了分块发送（`mouseMoveChunked`，每次 ≤120），
> `MOVE` 给多大的数都走得对。长距离拖拽同理由它保证。
>
> 另外固件新增了 `DRAG btn dx dy [steps]`：按下 → 分段移动 → 松开**一条指令原子完成**，
> 客户端对应 `decision/input.py` 的 `mouse_drag()`。程序化拖拽用它，
> 触控板那种跟手指走的拖拽仍用 press/move/release 三件套。

**前提（必须做，否则坐标全是错的）**：

- 游戏机 Windows：指针速度固定 **6/11（默认档）**，**关闭「提高指针精确度」**
  （开启加速会让 count→px 变成非线性，映射立刻失效）
- 标定系数 `counts_per_px`（或反向的 `px_per_count`）

**标定工具（建议做成一次性脚本，放游戏机上跑）**：

```
循环：
  撞角归零 → 发 MOVE 固定的 (dx, dy) → 用 win32api.GetCursorPos() 读回真实落点
→ 自动算出系数，顺便验证线性度（多点采样，看偏差是否稳定）
```

比人工目测可靠得多，而且能顺手验证「加速是不是真关了」。

**误差预算**：需要 ±50px 级（见 3.2）。标定后如果残差在 ±20px 以内就很安全。

### 6.2 鼠标定位 —— 备选方案 B：改固件加绝对坐标 HID

让 Pro Micro 额外暴露一个 absolute pointing device，直接设定光标位置。

- 优点：精度最高、可重复、完全不受系统指针速度/加速影响
- 缺点：要改固件 + 处理 Windows 对绝对设备的识别

**当前不需要**（3.2 的精度要求用 A 就能满足），仅作为 A 走不通时的后路记录。

#### 五个坑（都踩过，写下来免得重犯）

**1. 锚点不能含账号等用户数据。**
第一版拿整个登录木牌当锚点，里面带着账号 `15359879262` —— 换个账号就匹配不上。
锚点必须是「什么账号都一样」的元素。

**2. 看着很标志性的东西未必是界面独有的。**
CADPA 12+ 适龄提示框（右上角蓝框）第一版被当成登录界面的锚点，实测它在
12.5s（选频道）时分数仍是 **1.000** —— 它从登录一路跟到选角，不是登录独有。

**3. 「登录那段」其实是三个子状态，不是一块。**

| 时间段 | 画面 | 判据 |
|--------|------|------|
| 0 ~ 2.5s | 登录木牌 + **断线提示框** | `login_err` ✓ |
| 3.5 ~ 5.0s | **登录木牌可见**（等按「连接」） | `login` ✓ |
| 5.5 ~ 11.5s | **木牌已收起，只剩背景**（连接中） | **判不出来 → None** |

第三段是「按了 Enter（= 点了连接）之后、服务器还没响应」的过渡态，画面上
只有登录背景插画，没有任何独有 UI。**它和「在游戏里跑图」一样返回 None**，
所以 `detect()` 的 None 不能理解成「在游戏里」——上层必须靠别的信号区分。

对本期需求没影响：**断线后客户端会停在木牌可见的状态等用户按「连接」
（即 3.5~5.0s 那种），这正是要判的目标。**

**4. 「选择频道」和「选择角色」的标题在同一位置、同一块深红标牌上，必须只裁文字。**

第一版锚点裁的是整块标牌 (20,40,135,45)，红底占了相关性的大头 ——
实测把「选择频道」的模板打在选角界面上仍有 **0.82**（阈值 0.80），于是选角被误判成
选频道、走了「点服务器」这一步。改成只裁文字 **(38,64,120,32)** 后：自帧 1.00、
对方界面 0.64，余量足够。

**5. 锚点里绝不能含会变的数字。**

排队弹窗第一版锚点顺手裁了「排队者 11 名」那一整行 —— 人数是变的，换个队就匹配不上。
避开人数（只用两行固定文案 + 「取消」按钮）后真帧 ≥0.995。

#### 性能与分辨率

- 全分辨率（1920×1080）单个锚点要 **116.7 ms**，太慢；缩到 0.5 倍后 21 ms/锚点，
  七个锚点整帧扫是 **100 ms/次**，还是偏重。
- **只锚点位置附近搜**（`SEARCH_MARGIN = 60px`）：UI 是固定布局，不需要整帧扫。
  7 个锚点合计降到 **3.4 ms/次**（快 30 倍），顺带也压低了误命中。
  代价是 UI 偏移超过 60px 就找不到 —— 但整帧缩放（`prepare`）已经保证了位置稳定。
- 模板按 1920×1080 裁，判别时把整帧缩到基准的 `MATCH_SCALE`（0.5）倍再匹配 ——
  换分辨率不用重裁模板，前提是游戏 UI 随分辨率等比缩放（且画面宽高比是 16:9）。

#### 界面覆盖情况

六个界面全有了（见上表）。**「回到游戏」不靠 UI 锚点判** —— 判不出来（游戏内没有
独有 UI），靠**玩家框重新出现**这个信号，所以 `detect()` 返回 `None` 绝不能理解成
「已经在游戏里」，上层必须靠玩家框区分。

### 6.4 重连状态机 —— ✅ 已实现（`decision/reconnect.py`）

界面 → 动作的映射写在 `STEPS` 里：

| 界面 | 动作 | 说明 |
|------|------|------|
| `login_err` | `enter` | 消掉断线提示框 |
| `login` | `enter` | 点「连接」 |
| `channel_list` | `click` | 点服务器 —— **要鼠标，还没接** |
| `channel_panel` | `click` | 点频道 —— **要鼠标，还没接** |
| `queue` | `wait` | 排队，等它自己过去（长超时） |
| `char_select` | `enter` | 进游戏 |

**三条安全绳**（少一条都可能乱点）：

1. 只在**玩家框丢了**之后才探界面 —— 被树挡住、走出视野也会丢框，所以还要有第 2 条；
2. 探到的必须是**已知的断线界面**才动手；判不出界面时**绝不动**
   （判不出还乱按，就可能在游戏里狂发 Enter）；
3. 界面变了才立刻做下一步；界面没变则等超时重试，重试到上限**放弃并报警**
   （放弃时不恢复自动，宁可停着也不带着错误状态继续打）。

**每个动作前都已经确认过界面** —— 这是防「误点删除角色」的关键。

其它实现细节：

- **探界面限流 1 秒一次**（`PROBE_INTERVAL`）。判不出界面时**保留上一次结果**，
  因为界面切换中间会有一两帧判不出来，立刻清掉会让状态机以为「界面变了」而重复动作。
- **状态文字挂 30 秒**（`NOTE_KEEP`）才清。一帧就清的话，「已放弃，原因是 X」
  这种最该给人看的结论会瞬间消失。
- 排队用独立的**长超时**（默认 180 秒），不算失败重试。

### 6.5 触发与接入点 —— ✅ 挂在 `gui/live_thread.py`

**没挂在 `agent.tick` 的玩家丢失分支上**（原计划的 6.5），原因：**那里拿不到画面帧**。
`agent.tick` 只拿到 `WorldState`（框和平台，没有像素），而界面判别要原图。
所以挂到了 live_thread 推理循环里 —— 那里既有帧，又能直接控制 `settings.enabled`。

位置在**画框之前**：此刻 `vis` 还是干净帧，画上玩家蓝框 / 平台线之后会干扰模板匹配。
注意 `player_found` 要用追踪器刚返回的结果，不能用「跟丢时拿上一帧兜底」的那个
`player_box` —— 那个永远不为 `None`。

**探界面的时机**：玩家框一丢就开始探（默认 `reconnect_probe_after_lost_sec = 0`）。
一开始想等 5 秒再探（怕被树挡住浪费算力），但**断线提示框只显示两三秒**，
等 5 秒就错过了，客户端会一直卡在提示框上等人按确定。而窗口匹配后单次 detect 只要
3.4ms，不值得为省这点开销推迟。

**状态怎么给人看**：状态文字写进 `settings.reconnect_note`，随统计信号回传，
显示在实时面板统计栏最前面（`【检测到断线提示框 —— 已停止自动】 …`）。

**进游戏怎么判**：玩家框重新出现 → 结束重连；`reconnect_resume_auto` 开着就恢复自动。

### 6.6 排队弹窗

排队可能很久（素材里 11 名等了 2s，实际可能几十秒~几分钟）。
用**长超时 + 轮询**，不要当成失败重试。

1. ~~客户端是否记住上次的服务器~~ → **基本确认记住了**：服务器列表只露 0.75 秒，

**还要确认的**（真要动手才知道，按重要性）：

1. **鼠标标定的可行性**：游戏机 Windows 的指针速度是不是 6/11、有没有开「提高指针精确度」。
   开了加速就没法线性映射，得先改系统设置（§6.1）。
2. **单击频道是否立即进入**？素材 15.0s → 16.5s 之间的逐帧还没看（那时面板弹出 + 排队）。
3. 排队**最长**多久（默认给了 180 秒）。超了会放弃，要不要报个警？
4. **断线后是不是每次都停在同一个服务器**（蓝蜗牛）？换角色 / 换区会不会变。
5. 游戏客户区在游戏机上是否固定 `1920×1080`（素材是）、是否无边框窗口

   （状态机的 `login_err` 步骤现在是发 Enter）。
7. 断线后客户端有没有可能直接弹**别的**弹窗（公告 / 活动）挡住流程 ——
   现在碰到判不出的界面就等，要不要加「点掉未知弹窗」的兜底。

## 附录 A：重新抽帧（本文的坐标都靠它复核）

```python
# 顺序读取（不要用 set() + retrieve()，那样不推进帧号，会重复拿到同一帧）
import cv2
c = cv2.VideoCapture(r'datasets/records/断线重连素材.mp4')
fps = c.get(5)
want = {0.0, 1.0, 12.0, 15.0, 16.5, 18.0, 19.5, 24.0}   # 想要的时间点
i = 0
while True:
    ok, fr = c.read()
    if not ok:
        break
    t = i / fps
    for w in list(want):
        if abs(t - w) < 1 / fps / 2:
            cv2.imwrite('frames/f%05.1f.png' % t, fr)
            want.discard(w)
    i += 1
c.release()
```

裁模板时盯住这些区域（**坐标是估算值，需复核**）：

- 「选择频道」标题：约 `x 0.02~0.08, y 0.03~0.06`
- 服务器名行：约 `y 0.18`，第 1 个服务器约 `x 0.28`
- 频道面板：约 `x 0.30~0.60, y 0.32~0.58`
- 频道格子：约 `147 × 55` px（1920 宽下），面板内 4 列 × 5 行
- 「开始游戏」木牌：右下，约 `x 0.60~0.72, y 0.32~0.45`

**已复核确认**（重新抽 15.0s 帧放大核对）：

- 频道面板是 **4 列 × 5 行 = 20 个/页，行优先**
  （第 1 行 `频道1~4`、第 2 行 `频道5~8`、第 3 行 `频道9~12`，依此类推）
- 「蓝蜗牛」大标题在面板左上，是很好的面板锚点
- 面板右侧有滚动条（但见 3.2：本期不需要翻页）

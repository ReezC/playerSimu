## 1. 滚轮不许改参数（硬规则，没有例外）

**现象**：想滚页面，指针顺路划过参数框 —— 数字被改了，而且**没有任何提示**。
更隐蔽的是「聚焦残留」：点过一次数字框后焦点还留在那儿，之后再滚页面，
滚轮仍被当成「在调这个参数」。

**所以：所有参数控件都不响应滚轮 —— 但页面必须照滚。**

> **作用域（2026-09-26 补）**：这条只管「**值类控件**」——数字框、下拉框、滑块、标签栏。
> **滚轮该干的活照干**：滚页面、**缩放画布**。视图类操作一向就用滚轮，这是仓库里的
> 既定做法（`gui/verify_viewer.py`、`gui/minimap_calib.py` 的操作提示都写着
> 「滚轮=缩放　中键拖=平移　双击=适应窗口」；`gui/widgets.py` 开头也写着
> 「滚轮专心滚页面 / 缩放画布」）。
> **别把这条读成"哪儿都不许用滚轮"** —— 我自己就这么读错过一次，还把画布缩放设计成
> `+`/`-`，被纠正了。新增视图/画布时：滚轮缩放、中键拖平移、双击适应，照旧。

三条一起做：

| # | 做法 | 说明 |
|---|------|------|
| ① | 参数控件一律用 `gui.widgets` 里的 `NoWheelSpinBox` / `NoWheelDoubleSpinBox` / `NoWheelComboBox` / `NoWheelSlider` | 它们的 `wheelEvent` 会**代为滚动外层滚动区** → 参数不变、页面照滚 |
| ② | 应用启动时装一次全局守卫 `install_wheel_guard(app)`（已在 `gui/app.py`） | 兜底：谁忘了用 NoWheel*，滚轮也不会改值，同样代为滚页面 |
| ③ | `from gui.widgets import ...` **必须写在模块顶部** | 写在方法/类体里是局部名字，构造函数里用到就 `UnboundLocalError`（本仓库炸过一次） |

**不允许**：裸用 `QSpinBox` / `QDoubleSpinBox` / `QComboBox` / `QSlider`；
也不要「在 `wheelEvent` 里把值改回去」这种写法。

守卫还顺带管了 **标签栏**（`QTabBar` 滚轮会切页，同样是误触）。

### 实现要点：不要写 `ev.ignore()` 就完事

常见说法是「`wheelEvent` 里 `ignore()`，事件就冒泡给父级滚动区」。**这里不能靠它**：
那条链路依赖平台层怎么派发滚轮，细节不由我们控制 —— 实测无头环境下合成事件 +
`ignore()` 时外层 QScrollArea 纹丝不动（而视觉症状就是「指针压在参数框上页面不滚」）。

统一用 `gui.widgets.forward_wheel(ev, widget)`：它找**最近的外层
`QAbstractScrollArea`**，按「系统滚轮行数 × `singleStep`」直接驱动滚动条
（触摸板的 `pixelDelta` 按像素算，Shift + 滚轮 = 横向），内层滚到头就继续往外找，
嵌套滚动区也能用。转发成功要 `ev.accept()`，否则外层可能再滚一遍。

**QScrollBar 必须放行**：它也是 `QAbstractSlider` 的子类，被守卫吃掉的话，
指针压在最右边那条滚动条上时页面就不滚了。

**数字框的 `wheelEvent` 根本不会被调用**：`QAbstractSpinBox` 在 `event()` 里
就把滚轮忽略掉了（不是交给 `wheelEvent`），所以「只在 `wheelEvent` 里转发」
对 `QSpinBox` / `QDoubleSpinBox` 无效。真正兜住它的是 `_WheelGuard` ——
守卫在事件到达控件**之前**跑，对 `NoWheel*` 也代为转发一次（转成功就 accept，
免得再冒上去滚两遍）。所以守卫不能只盯着裸控件。

**控件在滚动区外面**（比如置顶常驻的组）：往上永远找不到滚动区，就在它的
容器上挂一个 `_wheel_target` 指向那个滚动区，`forward_wheel` 会认这个指路
（见 `gui/player_panel.py` 的「操控」组）。

> 检查项①③由 `tools/check_ui.py` 强制；②是兜底。

## 2. 新增一个参数的清单（最容易漏，一次漏一个坑）

| # | 做什么 | 漏了会怎样 |
|---|--------|-----------|
| 1 | `DecisionSettings.__init__` 加字段，**注释写清单位 + 0 的含义** | 下次没人知道 0 是关闭还是真的 0 |
| 2 | `to_dict` 加键 | 改完存不下去，重启就丢 |
| 3 | `from_dict` 读键（**要有默认值**） | 重启就丢 / 旧配置直接崩 |
| 4 | GUI 加控件 + `setToolTip` + `valueChanged` → 写回 `settings` 再 `save()` | 配了不生效 |
| 5 | 载入/切换时**用 `blockSignals` 回填控件值** | 回填触发 `valueChanged` → 把默认值写进配置，或者把配置覆盖成默认值 |
| 6 | 决定**存全局还是按项目**（HP/MP 条是按项目存的，见 `project.yaml` 的 `bars`） | 换个项目参数就串了 |
| 7 | 键名要改的话，**兼容读一次旧键** | 别人的旧模板/旧配置直接失效 |

> 「运行时状态、不持久化」的字段请显式写在 `__init__` 里那句
> `# 以下是运行时状态，不持久化（to_dict 不导出）：` 之后，或在字段注释里写上
> **不持久化** 三个字 —— `tools/check_ui.py` 靠这个标记区分，否则会误报。

## 3. 信号与回填

- **改了立刻 `settings.save()`**。本项目没有「应用」按钮，参数是即时生效的
  （字号除外，它走 `theme.apply` 立即生效但不用 save）。
- **回填一律 `blockSignals(True/False)` 包住**，不要用 `if value != xxx` 绕。
- **后台线程写、界面只读的量用轮询同步**（例：`_poll_auto_state` 定时读
  `settings.enabled` 刷新按钮状态）—— agent 在实时线程里也会改 `enabled`。
- 跨线程一律用 `pyqtSignal`，**不要在后台线程里直接 setText/setValue**。
- **要"边用主窗口边用"的窗口一律非模态**（`show()`，不是 `exec_()`）+ **单实例**（挂在主窗口上，
  再点一次只 `raise_()`/`activateWindow()` 提到前面）+ 结果靠**信号**回传
  （`exec_()` 那条返回值没有了 ⇒ 必须主动通知，否则"存了但外面没反应"）。
  例：`gui/zone_editor.py`（`saved_now` —— 圈集合要照着实时页的画面判断、还要反复核世界坐标）、
  `gui/two_point_calib.py`（`saved_now` —— 量标定要一边开预览、看世界读数、对着叠图核）。
  ⚠ 模态与非模态**界面长得一模一样**，谁改回 `exec_()` 都不会察觉 ⇒ 用用例钉住：
  `tools/selftest_minimap.py` 的 `t_two_point_dialog_nonmodal`（窗口 `isModal()` 为假 +
  入口那段是 `dlg.show()` 而不是 `dlg.exec_()` + 回传线在位）。
  ⚠ 反过来，**"问一句再继续"**的窗口（设置、导出、框选）该模态就模态 —— 它们本来就是
  "停下来做完这一件"。
- **非模态的窗：关掉只是隐藏，别销毁**（`close()` 不 dispose ⇒ 用户填的东西留在控件里；
  重新 `show()` 时自己把后台那一路接回来，见 `gui/two_point_calib.py` 的 `showEvent`）。
  ⛔ 别按"`not dlg.isVisible()` 就重建"写 —— 那会让**每次关窗都丢数据**（用户 2026-09-27
  报的"关掉双点标定弹窗后，上次的数据就丢了"就是这个 ✗）。要重建只有两个正当理由：
  **换了地图 / 换了来源**。
  ⚠ 隐藏态留着的还有**上次算出来的结果** ⇒ 数据一改就要把它作废（否则"改了数忘了重算、
  直接点保存"会写上一版）。
- ⭐⭐ **改了参数，界面上"由它算出来的状态文本"必须当场跟着变**（2026-09-29 新增 ✓）。
  任何"**读别的控件、算出一个结论、写成文字**"的行都属于这一类（例：② 采集的
  「预估约 N 张」← 由**文件 + 抽帧间隔 + 最多张数**算出 ✓）。它必须满足**四件事**：
  1. **每个上游控件变化都要重算**（`valueChanged` / `currentTextChanged` …）；
  2. ⚠⚠ **信号连接一律写在 `build_params()` 的末尾** —— 控件是**按顺序创建**的，
     写在靠前的位置时**后面的控件还不存在** ⇒ `self.widgets.get("xxx")` 拿到 `None`
     ⇒ **连接静默失效**（不报错、看着像写了）✗。2026-09-29 实测：把
     `stride.valueChanged` 连在 `file` 字段后面 ⇒ 用户改「抽帧间隔」数字**纹丝不动** ✓；
  3. ⚠ **回填之后也要刷一次**（`load_from_project` 里）：只靠"用户点「浏览」"那种
     回调**不够** —— 从项目文件回填时会一路显示占位符 `—` ✗（明明有值却不显示，
     看着像功能没做 ✓）。⚠ 要加在卡片**已有的** `load_from_project` 里，
     **别新增同名方法**（会把原实现整个顶掉 ⇒ 回填失效 ✗；`pyflakes` 会报
     `redefinition of unused '...'` ⇒ **这条警告一定要看** ✗）；
  4. ⚠ **不适用时要说清或藏掉**：占位符别留旧值 ✗（切来源 / 切模式时要清或隐藏；
     注意**不是 `field()` 建的控件不受 `set_row_visible` 管** ⇒ 得自己 `setVisible` ✓）；
     算不出来的情况要**说明白**（"这个文件没报总帧数" / "（是估的）" / "已被封顶" ✓）
     —— 别让人把估算当精确值 ✗。
  ⚠ 用例要**走真正的 UI 信号**测（`spin.setValue(12)` ⇒ 断言文本变了 ✓），
  **不要直接调那个刷新方法** ✗ —— 直接调就绕过了"连接有没有接上"这件事，
  而这次坏掉的恰恰就是连接 ✓（`tools/selftest_live_panel.t_capture_est_frames`）。

## 4. 布局与分组

- **通用参数放通用组，策略专属参数放策略组并随策略显隐**
  （见 `_refresh_strategy_ui`：`sp_turn_cd` / `sp_back_range` 只在「扫平台」时可见）。
  不要把一个通用参数塞进某个策略的专属区 —— 换策略它就不见了，用户以为丢了。
- **代码顺序 = 视觉顺序**。要挪位置就整块代码搬，不要只在最后补一句
  `root.addWidget(...)`（那样下次改这组代码会找错地方）。
- **一行只放一个参数组；放不下就另起一行，不许顺着行尾继续 `addWidget`**。
  一行里堆到三组以上之后，窗口一窄就是所有标签一起被压没 —— 最后只剩几个看不出
  是什么的下拉框；而且再也说不清哪几个参数属于一件事。
  现成的例子：`gui/route_panel.py` 的「小地图定位」拆成两行 ——
  第一行「这是哪张图 · 怎么显示」，第二行「画面从哪来 · 框选/标定动作」；
  ⭐ **2026-09-29 又清掉最大的一处存量**：`gui/live_panel.py` 的参数行原来**一行挤了
  10 个控件**（权重 / 怪conf / 玩家conf / imgsz / 设备 / 抓帧fps / 画框 / 延迟探针 /
  探针框 / 框选探针 ✗）—— 按「你在干什么」拆成三行：**推理参数**（权重 / 阈值 /
  分辨率 / 设备）、**抓帧与显示**（抓帧fps〔仅窗口来源〕/ 画框）、**延迟探针**
  （开关 / 探针框 / 框选探针）✓。拆的时候顺手把行里一个 `setFixedWidth(50)` 改成
  `setMinimumWidth + setMaximumWidth`（见下面「别钉死」那条 ✓）。
  加新参数时**先归组、再决定放哪一行**：它跟谁是一件事？那一行还塞得下吗？
  塞不下就自己起一行，别接着往右续。
  每个多行参数区的行尾都留一句注释点明「这一行到这儿结束」，下一个人才不会顺手续上。
- ⭐ **「有意不放滚动区」也要写出来**（2026-09-29 遍历全项目 UI 时收口）：画布 / 画面
  必须常驻的页（质检台 `gui/review.py`、验证浏览 `gui/verify_viewer.py`、
  实时页 `gui/live_panel.py`、角色匹配页 `PlayerMatchPage`）**整页不放滚动区是
  有意的** —— 画布（QGraphicsView）本来就不许进滚动区（§4 上面那条 ✗），画面要
  常驻占满；这些页必须在布局代码开头留一行注释说明取舍，否则下一个人会当成
  「漏做了」再去补一个滚动区，把画布塞进去 ⇒ 退出 `0xC0000005` 的老坑就回来了 ✗。
  对照的正面例子是 `player_panel` / `route_panel`：**参数区滚动 + 画布常驻** 的两段式 ✓。
- 长面板放进 `QScrollArea`。
  - ⚠ **它必须真的接上**（2026-09-27 用户报："路线识别页签不支持滚动？现在攀爬参数组的行和行
    都重叠了"）：页面直接 `QVBoxLayout(self)` 时，内容比页签高 ⇒ Qt 只能**硬挤** ⇒ 卡片里
    相邻的行被压到**重叠**（"不能滚"和"行重叠"是同一个病 ✓）。
    **实现只有一处**（`tools/check_ui.py::check_scroll_single_impl` 强制，2026-09-27 收口）——
    `gui/widgets.py` 是唯一 `new QScrollArea` 的地方，按场景挑一个入口：
    | 入口 | 什么时候用 | 返回 |
    |---|---|---|
    | `scroll_page(widget, margins=, spacing=)` | 页面 = **空容器 + 一堆卡片**（参数页 ✓）；`margins/spacing` 用这一页原来的值 ⇒ 观感不变 ✓ | 里面那层**布局**（照旧 `addWidget` ✓） |
    | `mount_scroll(layout, content, stretch=)` | 内容**自带样式/自建控件**（部署台的 `QFrame#Card`、左栏卡片列 ✓） | 滚动区控件 |
    | `scroll_area(content)` | 滚动区自己要**当一个控件交出去**（`QSplitter` 的某一栏 ✓，需要 `h_scroll=True` / `min_width`） | 滚动区控件 |
    ⛔ 别再手抄 `QScrollArea()` + `setWidgetResizable(True)` + `setWidget(...)` 那三行 ✗ ——
    这仓库手抄过 **7 份**，结果就是**有的页能滚、有的页不能滚**（用户报的路线识别页就是漏的 ✗）。
    确需自己写：在那一行加 `# ui-allow-scroll：<理由>`（现在**只有一处**：
    `gui/player_panel.py` 的「操控」常驻栏 —— 它要拿滚动区**实例**当 `_wheel_target` 指路 ✓）。
  - ⚠ **"滚动视图"不许放进滚动区**（2026-09-27 实测的坑）：`gui.canvas.ImageCanvas` 是
    `QGraphicsView`（**它自己就是个滚动视图**）—— 套进外层 `QScrollArea` 之后，工作台
    **退出时会偶发 `0xC0000005`**（access violation；实测 8/8 崩 ✗；把画布换成普通控件
    立刻 8/8 好 ✓）。版式照 `gui/player_panel.py`：**参数区滚动、画布常驻**
    （`card(..., into=self.layout())` 把那张卡片加在**外层**布局上 ✓）。
    用例：`selftest_minimap.t_route_panel_scrolls`（⑥ 专门钉"画布不在滚动区里" ✓）。
  - **常驻区太占地方 ⇒ 用「可拖动的两栏」**（2026-09-27 用户："寻路配置的地形图……太占位置了"✓）：
    「路线识别」页现在是 `QSplitter(Qt.Vertical)` —— **上栏 = 参数区（滚动区）、下栏 = 地形图**
    （`gui/route_panel.py::__init__`），拖分隔条就能决定地形图占多高 ✓；
    按 §4 的口径：`setHandleWidth(6)` + **`setChildrenCollapsible(False)`**（不许拖成 0 ✓）+
    **两栏的最小高度由人定**（参数区 240 / 地形图 170），`setStretchFactor` 让参数区先长 ✓。
    ⚠ **踩过的坑（务必记住）**：`card(..., into=...)` 里**不许**写 `(into or page)` ——
    **PyQt 的空布局是"假"的**（`QLayout` 有 `__len__` ⇒ 刚建好、还没装东西时 `bool() == False`）
    ⇒ 新栏那个空布局会被当成 falsy、卡片又落回参数页（画布就这么进了滚动区 ✗，
    正是 `t_route_panel_scrolls` ⑥ 抓出来的）⇒ 一律**显式判 `None`** ✓。
  - 画布**内容的**缩放不用另做：`gui.canvas.ImageCanvas`（= `ZoomPanView`）本来就是
    **滚轮缩放 / 按住中键平移 / 双击适应窗口** ✓（`canvas.py`）—— 界面上把这三条写进 tooltip 即可 ✓。
- 多列用 `QGridLayout` / `addStretch`，别靠固定宽度对齐 —— 缩放窗口就散了。
- **多栏（≥2 栏）用 `QSplitter`**（栏宽可以拖）+ **每栏一个 `QScrollArea`**：栏宽由人调，
  窗口矮下来是"栏内出滚动条"，不是把按钮压没。`setChildrenCollapsible(False)`（不许把
  某一栏拖成 0 宽 —— 拖没了就找不回来）。例：`gui/zone_editor.py` 的三栏
  （画布 ｜ 集合 ｜ 可达 / 可被到达）。
- ⚠ **栏的最小宽度要"人定"，别让内容算**：`QSplitter` 的最小宽度 = **各栏最小宽度之和**，
  而按内容算出来的值会一路顶到窗口。实测（`gui/zone_editor.py` 三栏）：集合栏内容要 256、
  可达栏要 276、画布栏 308 ⇒ 对话框最小宽度 **702**，而这条窗口只允许 **620**
  （用例 `t_window_can_shrink_vertically`）。把三栏的 `setMinimumWidth` 定成
  244 / 160 / 170 之后回到 **608** ✓；栏内内容比这个宽时**出横向滚动条**
  （`ScrollBarAsNeeded`），而不是把按钮切掉。
- ⚠ 同理，**一行里的控件别用 `setFixedWidth` 钉死**：`QSlider` 用了 `setFixedWidth(160)`，
  就把"底图透明度"那一行、进而把**画布整栏**的最小宽度钉到 308。要"平时这么宽、挤的时候
  能缩"就写 `setMinimumWidth(96) + setMaximumWidth(160)`（zone_editor 的 `sl_bg` 就是这么改的）。
- **框选一律走同一份实现**（实时页框选区域 / HP-MP 条 / 探针框选都是它）：
  **交互全在 `gui/region_picker.py`**（`select_on_pixmap` / `select_screen_region`）；
  B 机侧的入口是包一层的 **`gui/region_selector.py`**（numpy→QPixmap +
  `core.wincap` 跨显示器抓屏），A 机部署台没有 numpy/wincap，直接用 `region_picker`。
  指针旁边带放大镜（21×21 源像素、默认 ×8、`+`/`-` 可调、像素网格 + 准心），
  拖拽时自动挪到框的外侧。**重写框选别把这个放大镜弄丢** —— 框选常常只差一两个像素。
  实现要点：放大要 `SmoothPixmapTransform=False`（平滑会把两个像素糊成一个，
  那就白放大了）；只重画放大镜那一小块，别每次整屏重画。

## 5. 线程

**任何会阻塞的事情都不许放主线程**：连网络、开串口、加载模型、等待设备回应。
做法：后台线程干活 → `pyqtSignal` 回主线程改 UI。

反例（本仓库真实踩过）：`_apply_input_device` 里直接连远程键盘，界面卡住几秒；
后来的做法是起线程 + `device_connected` 信号。
同理 `_reset_link`（重置指令通道）重连前先 `QApplication.processEvents()`
把「正在重连…」画出来，否则用户以为按钮没反应。

## 8. 框选一律带放大镜

**所有框选都走 `gui/region_picker.py`**（`select_on_pixmap` / `select_screen_region`），
不许再各写一份 —— 以前 B 机一份、A 机部署台又一份（那份还没有放大镜）：

- **默认带放大镜**：跟着光标、21×21 个源像素、默认 8×（细长目标如 HP/MP 条可以
  由调用方给起点，例如 12×），`+` / `-` 调 4~16 倍。
  **放大镜的「倍数」不用滚轮**（`+`/`-` 是唯一入口）—— 这里指的是**倍数这个值**，
  不是说框选窗口里不许有滚轮视图缩放（§1 的作用域只管值类控件）；
- 放大镜带**像素网格**（≥6× 显示）和**准心**（准心 = 光标那一个像素），
  说明条写出「源图坐标 + 当前倍数」；窗口左上角常驻一行 `+/-`、`Esc` 的提示
  （`+/-` 是唯一的倍数入口，不写出来没人知道）；
- **不压住光标**：拖拽时自动挪到框的外侧；贴边时整体平移，准心始终指真实像素；
- 框外压暗、框内原亮、框边标尺寸；`Esc` 取消；**小于 4px 的框视为误点**（不返回，
  而不是返回一个几像素的"区域"）；
- **抓屏前先把调用方窗口藏起来**（`select_screen_region(hide_owner=True)`）：
  不藏的话截到的图里盖着工作台/部署台自己，人对着自己的界面框游戏里的东西；
- **框选「框的那张图」必须是原生帧**（2026-09-27 用户现场，见下）：
  `live_panel.current_frame()` 给的是**从推流里解出来、没画过任何东西**的那一份。
  检测框 / 攻击线 / **视野灰色虚线**都画在**显示帧**上（收流线程分两路发：
  `raw_frame_ready` = 原生、`frame_ready` = 显示 ✓），**显示帧不许从 `current_frame()`
  出去** ✗。用户 2026-09-27 报的正是这个：**框选小地图时把视野灰色虚线一起框了进去**
  —— 那条虚线会跟着被裁进小地图面板里，之后匹配分、叠图、定位全脏 ✗。
  用例：`t_current_frame_is_raw`（面板侧）、`t_raw_frame_before_draw`（线程侧：
  先留原生帧、再就地画，且只有真要画时才拷 ⇒ 收画面阶段零开销 ✓）。
- **框完当场验证**：能验的就当场验，别让人靠感觉 ——
  · 探针方块带 → 当场解码，解不出**不保存**（`gui/live_panel.py::_pick_probe`）；
  · 小地图面板 → **框完立刻给匹配分**（本页「寻路配置 → 框选小地图」；
    来源选「从实时画面框选」时，框完当场就在状态行算一次分，不用等标定那一步）；
    来源选「收流」时 A 机只负责框，匹配分在 B 机标定弹窗里给；
  · HP/MP 条 → 采样填充色并显示（`gui/player_panel.py::_pick_bar`）。
- ⚠ **"框对不对"和"标定准不准"是两件事，别混**：前者是框完那一瞬的匹配分（上面那条 ✓）；
  后者是**整体几何偏了多少世界像素** —— 同一个「寻路配置」组里有「**实测精度**」按钮
  （只读，用户 2026-09-27 要求做成一次点击 ✓）：模板匹配当独立尺子，报世界像素偏差 +
  **尺子可信度**（匹配分 < 0.80 时明写"只能当参考"✗）。算法只有一份
  （`perception.minimap.check_calib`，命令行 `tools/mmap_calib_check.py` 共用 ✓）；
  用例 `t_route_panel_mmap_check` / `t_calib_check_and_reverse` ✓。

为什么写死这么细：框选差一两个像素的后果都不是"看着别扭"，而是**下游直接错** ——
探针错一个方块宽度整条时间码错位、血条错一像素采样到背景、小地图框大了 B 机
「底图对不上」（现象看着像寻路坏了）。所以框选是**功能**，不是顺手的小工具。

（A 机没装 numpy/opencv）；抓屏方式由调用方通过 `grab=` 注入（B 机用
`core.wincap` 跨显示器抓，A 机用 Qt 抓主屏）。

## 9. 数值控件：单位与精度（2026-09-26 新增）

**① 毫秒一律整数。** 凡是以毫秒为单位的参数（变量名带 `ms` / `millis` / 毫秒），
必须用整数控件（`NoWheelSpinBox`），**不许**用小数控件。

为什么写进规范：`_spin(lo, hi, val, decimals, step)` 这类工厂的第 4 个参数是**小数位**；
把"步进 50"写进第 4 位 ⇒ `decimals=50` ⇒ 框里显示 `0.0000000000000000000000000…`
（实测用户就是这么被坑到的 ✗）。毫秒没有小数意义，整数控件从根上避免这一类错。

**② 单位写在框外，不许写进编辑框。**

```python
# ✗ 不写：单位进了框，长数字被挤窄，value() 的显示里混着单位
self.sp_hold.setSuffix(" ms")
form.addRow("对齐保持时间", self.sp_hold)

# ✓ 这样写：单位在**表单行标签**里（或旁边放一个 QLabel）
self.sp_hold = NoWheelSpinBox()
form.addRow("对齐保持时间(ms)", self.sp_hold)
```

为什么：单位混进框内 ⇒ 数字和单位挤一起、读起来像"值的一部分"、同一个单位在不同页面
写法还不统一（`" ms"` / `"ms"` / `" 毫秒"`），查配置时对不上。

**自动检查**（`python -m tools.check_ui`）：

| 规则 | 判据 | 级别 |
|---|---|---|
| `check_ms_is_integer` | 变量名带 ms 却是 `NoWheelDoubleSpinBox` / `setDecimals(>0)` | **错误** |
| `check_unit_in_label` | 出现 `setSuffix(` | **错误**（2026-09-26 存量清零后升级） |

## 10. 键盘快捷键：焦点范围要「只在那一页」（2026-09-27 新增）
